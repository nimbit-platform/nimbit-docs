The permissions of the four system roles in every tenant, per resource type. Roles say what kind of action is allowed. [Groups](./access.mdx) say on which things.

## Reading the tables

| Letter | Action | Matrix column |
| --- | --- | --- |
| `c` | Create | **Create** |
| `r` | Read | **Read** |
| `u` | Update | **Update** |
| `d` | Delete | **Delete** |
| `x` | Execute | **Execute** |

A dash means the role has no permission on that resource. Resource names are as the permission matrix in **People & access › Roles** shows them. System roles cannot be changed. A user with several roles holds all their permissions together.

## What the letters mean for some resources

| Resource | Meaning |
| --- | --- |
| Action | `x` runs an action, such as a command to a thing. |
| VNC Server | `x` opens a VNC connection. |
| Knowledge | `r` reads the knowledge graph and its documents. `c`, `u` and `d` create, change and delete records and the Knowledge setup. `x` asks Nimble and uses the MCP tools. |
| Incident | `c` creates an incident by hand. `x` resolves and merges incidents. Only Admin can delete. |
| Incident policy | The same letters, for the policies and automations that open incidents, and for incident statuses, resolution reasons and custom fields. |
| ApiKey | `c` creates a key, `r` lists the tenant's keys, `u` changes a key or the key policy, `d` revokes a key. Modeler's `c` covers personal keys. |
| Gateway | `r` lists gateways and their keys, `c` creates one, `u` issues an onboarding code or revokes a key, `d` removes one. |

## Notes on the system roles

| Role | Note |
| --- | --- |
| **Admin** | Only role with Invitation, Theme, ApiKey, ServiceAccount, Gateway, Data deletion and Audit log. Has no create permission on User and Tenant; people join through invitations. |
| **Manager** | Reads reports but cannot create or change them. Works incidents and reads incident policies. |
| **Modeler** | Has no Rule, Destination, Job, Incident, Aas or Passport permission. Grant Aas or Passport explicitly through a custom role. |
| **Viewer** | Dashboards are read-only: a Viewer cannot create or change them. May create incidents, run actions, open VNC connections and ask Nimble. Keeps `crud` on Query. |

Older installations may also show roles taken over from earlier user management, such as **System Admin**, **Invitation** or **Theme Designer**. They appear as custom roles. **System Admin** holds `ru` on Aas and on Passport, as **Admin** does.

## Custom roles

| Rule | Detail |
| --- | --- |
| Type | Shown as **Custom** in the **Type** column. System roles show **System**. |
| Granting | You can only tick permissions you hold yourself. The others are locked. |
| Changing or deleting | Only a member who holds all permissions of the role can change or delete it. |
| Deleting | Users who had the role lose its permissions. |
