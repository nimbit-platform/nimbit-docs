Post warnings and errors from your things into a Microsoft Teams or Slack channel, a webhook, or ntfy. To see how this fits with events and incidents, read [Events, incidents and notifications](./events-incidents-notifications.mdx).

## Before you start

- You need a role that may create notification channels, and to send a test, one that may run them. The entry **Notification Channels** appears under **Settings › Configuration** when you have access.
- Get the address IoT Breeze posts to:

<Tabs groupId="channel">
<TabItem value="teams" label="Microsoft Teams" default>

In Teams, create a workflow that posts a received webhook request to a channel, for example from the template *Post to a channel when a webhook request is received*, and copy its URL. IoT Breeze sends an Adaptive Card message.

</TabItem>
<TabItem value="slack" label="Slack">

In Slack, add an incoming webhook to the channel and copy its URL.

</TabItem>
<TabItem value="webhook" label="Webhook">

Have the URL of the receiving system ready. Optionally choose a secret, so the receiver can check that a request came from IoT Breeze.

</TabItem>
<TabItem value="ntfy" label="ntfy">

Choose an ntfy topic. If you don't use the public ntfy server, have your server URL and token ready.

</TabItem>
</Tabs>

## Steps

1. Open **Settings › Configuration › Notification Channels** and select **Create channel**.
2. Enter a **Name**, for example `Plant 1 alerts`, and choose the **Channel type**. You can't change the type later.
3. Fill in the field of the type: **Teams workflow webhook URL**, **Slack webhook URL**, **Webhook URL** (and **HMAC secret (optional)**), or **ntfy topic**.
4. Turn on **Automatic routing** and set **Minimum severity** to **Warning**. Leave **Event types** empty to send all of them, or pick the ones this channel should get.
5. Leave **Enabled** on and save.
6. In the list, select **Send test** on the new channel and check that the message arrives. You can only test a saved channel.

## Check that it worked

The channel's row shows its routing, for example `≥ Warning`. Open the channel's **Delivery log**. The test message is there with the status **Sent**. After the next warning, a new delivery appears.

## If it doesn't work

- **The test never arrives**: the **Delivery log** shows why. **Pending** means IoT Breeze is still retrying. A delivery fails after 5 attempts. The Teams workflow may be switched off, or the URL was cut when you copied it.
- **The delivery log shows Failed**: **Error** shows the receiver's answer, for example `Teams responded 410`. Open **Edit channel**, enter the new URL, and save. Then select **Retry** on the delivery.
- **Some events never arrive**: check their severity against **Minimum severity**, and their type against **Event types**. Events that end a state, such as a thing coming back online, are not routed. Neither are incident notifications. See [Set up an incident policy](./incident-policy.mdx) to post once per incident.
- **The row says Action only**: **Automatic routing** is off. The channel only gets messages from actions and automations that name it.
