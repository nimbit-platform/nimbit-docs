# Application Database Structure

This page details the structure and components of our primary application database, which is based on PostgreSQL 16.

## Extensions Schema

Our database utilizes a dedicated `extensions` as a shared schema to house most of the PostgreSQL extensions. This approach offers several benefits:

- Centralized management of extensions
- Simplified access control
- Clear separation between core database objects and extension objects

All other schemas in the database have access to the `extensions` schema, allowing them to utilize the installed extensions as needed.

To create a new user and grant schema access, use the following SQL commands:

```sql
-- Create a new user
CREATE USER username WITH PASSWORD 'secure_password';

-- Grant schema usage
GRANT USAGE ON SCHEMA schema_name TO username;

-- Grant table privileges (adjust as needed)
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA schema_name TO username;
```

## Best Practices

1. **Schema Isolation**: Keep related functionality within its designated schema to maintain a clean and organized database structure.
2. **Least Privilege Principle**: Grant users only the permissions they need to perform their tasks.
3. **Regular Audits**: Periodically review schema contents and user permissions to ensure they align with current requirements.
4. **Documentation**: Keep this documentation up-to-date as you add new schemas or system users.

For more detailed information on managing schemas and users, please refer to our [Database Administration Guide](#).
