# Authentication

In this project, authentication is managed through a role-based access control system. Depending on your role, you will have access to different features and functionalities. This section explains the hierarchy of roles and what each user can do.

## Role Hierarchy

We have three main roles in the system, each with its own set of permissions:

- **Admin**
- **Modeler**
- **Viewer**

The roles are structured hierarchically, meaning higher roles inherit the permissions of the lower ones.

| Role    | Permissions                                                        |
|---------|---------------------------------------------------------------------|
| Admin   | Full access, including managing credentials, models, and pipelines. |
| Modeler | Manage models and pipelines but no access to credentials.           |
| Viewer  | View results only.                                                  |

:::info Hierarchy Overview
Admins have the most permissions, followed by modelers, with viewers having read-only access. Users with higher roles inherit the permissions of the roles beneath them.
:::

### Role Descriptions:

#### Admin
:::danger Admin Privileges
Admins have full control over the system, so make sure only trusted users have this role.
:::

Admins can:
- **Manage credentials**: Access and modify credentials used in the pipelines.
- **Full pipeline control**: Create, update, delete, and run both forecasting and anomaly detection pipelines.
- **View results**: See the results of all processes, just like a viewer.

Admins can access all features available to modelers and viewers.

#### Modeler
:::note Modeler Responsibilities
Modelers handle the forecasting and anomaly detection processes. They do not have access to credentials.
:::

Modelers can:
- **Run models**: Start and manage forecasting and anomaly detection processes.
- **Pipeline management**: Create, update, and delete forecasting and anomaly detection pipelines.
- **View results**: Access and view the outcomes of the models and pipelines.

Modelers do not have access to sensitive credentials but can fully manage the modeling processes.

#### Viewer
:::tip Viewer Role
Viewers have the least permissions and are only allowed to view the results of the pipelines.
:::

Viewers can:
- **View results**: Access and see the outputs of the forecasting and anomaly detection pipelines.

Viewers cannot make any changes to models, pipelines, or credentials. They are restricted to seeing the results generated by other users.

---

## How It Works

:::caution Access Control
Ensure that the right role is assigned to each user to prevent unauthorized access to sensitive features.
:::

### Accessing Endpoints
Each role is assigned specific permissions for accessing different parts of the application. Depending on your role, you will be able to perform various actions when interacting with the system's API or user interface.

### Endpoint Permissions

- **Admin Endpoints**: Admins have access to all API routes and can make any changes, from managing credentials to running models.
- **Modeler Endpoints**: Modelers can access all endpoints related to model management, but they won't be able to modify credentials.
- **Viewer Endpoints**: Viewers are restricted to read-only access, allowing them to see the results without making any modifications.

---

## Summary

:::success Summary of Roles
- **Admins**: Full control, including credentials and pipeline management.
- **Modelers**: Can create, update, and manage pipelines but cannot access credentials.
- **Viewers**: Can only view the results.
:::

If you need access to more features, your role might need to be updated by an admin.

:::tip
Make sure you're logged in with the correct credentials to access the features aligned with your role!
:::
