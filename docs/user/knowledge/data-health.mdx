Ask Nimble can only answer what the graph connects. **Settings › Knowledge setup › Data health** shows what landed and what is still loose. Its tabs are **Ingestion**, **Link review** and **Reconciliation**. The menu entry shows a badge with the number of open links.

:::note Not the Monitoring menu
The **Ingestion** tab is at `/knowledge/monitoring`, an older name. It is about knowledge sources, not device data. For devices use **Monitoring › Things**.
:::

## Ingestion

**Ingestion** shows the health of one staging source at a time.

1. Open **Ingestion** and pick a **Source**. Under **Graph health** you also see the checks below.
2. Read **Batches**: each is **Pending**, **Processed** or **Quarantined**.
3. Open **Needs review** for rows the last transform could not write. Each row says why: an alias that did not resolve, a missing source id, or a validation failure.
4. Open **Dead letters** for deliveries that failed. **Unresolved** ones need action.
5. Fix the mapping or the source data, then select **Run transform** or **Replay**.

**Open the mapping** on a source jumps to its mapping. **Replay** retries a dead letter; a replayed entry stays in the list as **Resolved**.

### Graph health

**Graph health** scores how well your records are linked. Select **Check now**, or let a reconciliation round check it. Each check shows a count, examples and a fix such as **Show records** or **Review**.

| Check | Why it matters |
| --- | --- |
| Records without a type | Their measures and properties come from the type. |
| Records without a location | Questions about a site or hall cannot find them. |
| Records linked to nothing | Only a question that names them can find them. |
| Relations without links | A declared relation nobody uses gives Nimble nothing to follow. |
| Links stored as text | A name in an attribute cannot be followed. Make it a relation. |
| Records without identifiers or aliases | Mappings and questions cannot find them by an ID or another name. |
| Records without a description | A description helps a question find the right record. |
| Documents not attached | A document about no record is found only by its text. |
| Measures that never reported | The type declares measures, but the device never connected. |
| Open links to review | Waiting for a person. |

Each result is **Critical**, **Warning**, **Info** or **OK**. Large counts can be over a capped sample.

## Link review

A source record can describe a device, for example a pump in an SAP export. When Knowledge cannot find the matching device on its own, the record waits here.

1. Open **Link review**. The **Open** tab lists records with their **Best match**, a score (**Strong match**, **Likely match**, **Worth a look**) and the reasons, such as same name or similar name.
2. Select **Review** on a record. Pick the device it describes (**This is the device**), or **None of these**.
3. Confirm. The identifier is saved on the device, so the next sync links it by itself.
4. To handle many at once, tick rows and use **Confirm best match** or **Reject**.

Other tabs: **Confirmed**, **Rejected**, and **Not on device** for links where saving the identifier on the device failed; use **Try again**.

Choose **Link in Knowledge only** to link without changing the device. If the device already has a different number, you are warned that replacing it unlinks whatever that number links to now. A near-identical number is flagged **Typo fix**.

## Reconciliation

A reconciliation round runs across all sources. It re-runs batches that have rows in review, makes links that now resolve, checks confirmed links and ranks open links again. A round never picks a link for you.

1. Open **Reconciliation**.
2. Choose a **Schedule**: **Off**, **Every hour**, **Every day** or **Every week**. Times are UTC.
3. Or select **Run now**.

Each round is listed with **Linked**, **Reopened**, **Still open** and **Batches re-run**, its trigger (**Manual** or **Scheduled**) and whether it **Stopped early**.

Changing the schedule needs permission to edit Knowledge (the built-in **Admin**, **Manager** and **Modeler** roles have it). Without it you see the schedule as read-only text,.

## Keep it healthy

- Run a first transform, then check **Ingestion** for rows in review.
- Work through **Link review** until the badge is gone.
- Set a **Reconciliation** schedule if sources keep sending data.
