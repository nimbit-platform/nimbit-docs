**Administration** is where you decide who can do what in your tenant, connect gateways and integrations, and set up the tenant itself.

You only see the entries you may use. A role that cannot manage users, for example, does not show **Users**. If an entry is missing, ask a tenant admin for a role with the right permissions.

## What is in this section

| Menu entry | What you do there | Page |
| --- | --- | --- |
| **Users** | Invite people, change their roles, remove them | [Users](./users.mdx) |
| **Groups** | Organise people and things in a tree that controls who sees what | [Groups](./groups.mdx) |
| **Roles** | See built-in roles, create your own | [Roles](./roles.mdx) |
| **Gateways** | Connect on-site Periscope boxes | [Gateways](./gateways.mdx) |
| **API keys** | Give scripts and integrations access | [API keys](./api-keys.mdx) |
| **Audit log** | See who created, changed or deleted things, thing types, groups and users | [Audit log](./audit-log.mdx) |
| **Tenant Settings** | Name, features, theme, email, statistics | [Tenant settings](./tenant-settings.mdx), [Data, packs and connections](./tenant-data-and-connections.mdx) |
| **Files** | Upload and organise files | [Files](./files.mdx) |

Two more entries can appear. **API scopes** is for platform admins only: it defines what API keys may be granted. **Feedback** is for the product team and not part of tenant administration.

## Where to start

1. Read [Roles](./roles.mdx) to know what each built-in role may do.
2. Build a [group](./groups.mdx) tree that matches your sites or customers.
3. [Invite users](./users.mdx), give them a role, and add them to groups.
4. Set up [tenant settings](./tenant-settings.mdx): name, logos and email.

:::info Roles and groups work together
A **role** says what a person may do, for example create things. A **group** says which things they may do it with. Someone needs both.
:::
