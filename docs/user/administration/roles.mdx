A role is a named set of permissions. You give roles to users, to gateways and to service accounts. Permissions are written per resource type, such as thing, dashboard or user.

:::info What you need
To open **Roles** you need to read roles and to create, edit or delete them. The built-in **Admin** role can.
:::

## The roles list

Open **Administration › Roles**. Each row shows the **Name**, the **Type** (**System** or **Custom**), the **Description** and the number of **Resources** the role covers. Use **Search roles** to filter.

## Permissions

A permission is one letter for an action on one resource type.

| Letter | Action | Matrix column |
| --- | --- | --- |
| `c` | Create | **Create** |
| `r` | Read | **Read** |
| `u` | Update | **Update** |
| `d` | Delete | **Delete** |
| `x` | Execute | **Execute** |

## Built-in roles

Four system roles exist in every tenant. You cannot change them (**System roles cannot be changed**).

| Role | For | What it may do |
| --- | --- | --- |
| **Admin** | Tenant administrators | Everything in the tenant: create, change and delete all resource types, manage users, roles, groups, files and tenant settings, themes, API keys and service accounts, gateways, and read the audit log. |
| **Manager** | People who run daily operations | Create, change and delete things, thing types, groups, files, rules, events, dashboards, canvases and mail templates. Change and delete users (but not invite) and read roles. Read reports. Work incidents and read incident policies. No themes, API keys, gateways or audit log. |
| **Modeler** | People who build data models | Create, change and delete things, thing types, interfaces, dashboards, events, reports and geofences. Create, change and delete files. Read users, groups and roles. May create API keys. |
| **Viewer** | People who only watch | Read things, dashboards, events, reports, files and most other resources. Dashboards are read-only: a Viewer cannot create or change them. May run actions and VNC connections, ask Nimble, and create incidents. |

Older installations may also show roles taken over from earlier user management, such as **System Admin**, **Invitation** or **Theme Designer**. They appear as custom roles. **Theme Designer** only manages themes.

:::tip Start with the built-in roles
Most teams need only **Admin**, **Manager** and **Viewer**. Create a custom role when none fits.
:::

## Create a custom role

1. Select **Create role**.
2. Enter a **Name** and a **Description**.
3. In the permission matrix, tick the actions for each resource. A dash means the action does not exist for that resource.
4. Save.

You can only grant permissions you hold yourself. Boxes for permissions you lack are locked. For the same reason, only a member who holds all permissions of a role can change or delete it.

## Edit or delete a custom role

Select a role to edit it, or select rows and delete them. The dialog asks **Delete the role?** first. Users who had the role lose its permissions.
