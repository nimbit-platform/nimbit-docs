The audit log records who created, changed or deleted **Things**, **Thing Types**, **Groups** and **Users**. It is read-only.

:::info What you need
The permission to read the audit log. The built-in **Admin** role has it.
:::

## Read the log

Open **Administration › Audit log**. Entries are listed newest first.

| Column | Shows |
| --- | --- |
| **Time** | When the change happened. |
| **Resource** | The kind of record. |
| **Reference** | The record's name or ID. |
| **Action** | **Created**, **Updated** or **Deleted**. |
| **What changed** | The fields that changed in this save. |
| **Actor** | Who did it: a person, an **API key**, or the system. |

## Filter

Use the filters above the table.

- **Resource**: one or more of Things, Thing Types, Groups, Users.
- **Action**: created, updated, deleted.
- **Actor**: one person.
- The time range: last 24 hours, 7, 30 or 90 days, last year, or all time.
- **Search by reference ID**: find the history of one record.

Select **Clear filters** to start again.

## See what changed

Select an entry to open its change. The dialog lists each **Field** with its **Last recorded value** and the **New value**. **Open** takes you to the record, if it still exists. **Show raw change (JSON)** shows the stored change, and **Copy JSON** copies it.

:::info Old values
The last recorded value comes from earlier entries. If an older change is not loaded, a value can be missing. A field cleared to nothing is not recorded.
:::

Each thing's detail page also has an audit view of the changes to that one thing.
