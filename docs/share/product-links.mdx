A product link is a web address printed on a product, usually as a QR code. It opens a public page with the fields and documents you publish for that thing or thing type, and nothing else.

:::warning A product link is not secret
It is printed on the product, so anyone who sees the product can open it. Publish only what you want public.
:::

## Before you start

- A tenant admin has switched on **Asset Administration Shell** and **Product links** under **Administration › Tenant Settings › Features**. Product links stay off while the AAS feature is off.
- For a thing's link, the thing is exposed as an Asset Administration Shell; see [Publish things as Asset Administration Shells](./asset-administration-shell.mdx). Otherwise the link shows nothing, and the tab says so.
- Seeing links, published fields and the preview needs the **Passport** read permission: **Admin**, **System Admin** and **Manager** have it. Creating and changing links, and publishing, needs the **Passport** update permission: **Admin** and **System Admin**.
- API keys cannot manage product links.

## Create a link and choose what it shows

1. Open the thing, or the thing type under **Settings › Onboarding › Thing Types**, and select the **Product link** tab.
2. Select **Create product link**. The link starts as **Not public yet**: it shows nothing to anyone until you activate it.
3. Under **Fields**, publish fields on the thing type. Select **Publish** on a field, and under **Value** choose **The type's value** or **Each Thing's own value**. A thing type's own link shows only fields with the type's value.
4. On a single thing, the fields are those published on its type. To keep one off this thing's page, turn off **Show on this Thing**. The field then shows **Hidden on this Thing**.
5. Under **Documents**, select **Publish** for each document to show. Visitors can download it.

Some fields can never be published, and the tab marks them:
- **Private: cannot be published**: a field declared private on the type, or one whose value a private field reads through a proxy.
- **Device-reported: cannot be published**: a value the device reports.

## Preview and activate

1. Check the **Preview** on the tab, or select **Open page preview** to see the full page. A banner says whether the page is public. Documents are listed in the preview but cannot be opened there.
2. Select **Activate**, and confirm **Make this product link public?**. From now on anyone with the link, or who scans its code, sees the page from the preview.

The QR code and **Print label** appear once the link is active.

## Print a label

1. Select **Print label**.
2. Choose a **Label size**: **Small**, **Medium** or **Large**. Optionally enter a **Caption**.
3. Under **Code type**, choose **QR code** or **Data Matrix**. Both encode the same link, so either opens the same page.
4. Select **Print**. Print at actual size (100 %), or save as PDF. The label shows the code and the link as text.

| Size | Label | Code | Smallest module | Caption |
| --- | --- | --- | --- | --- |
| **Small** | 40 × 32 mm | 20 mm | 0.40 mm | 1 line |
| **Medium** | 62 × 50 mm | 32 mm | 0.50 mm | 2 lines |
| **Large** | 90 × 72 mm | 48 mm | 0.60 mm | 3 lines |

The code size includes the blank margin around it. A QR code (ISO/IEC 18004) uses error correction level M on **Small** and Q on the larger sizes. A Data Matrix (ISO/IEC 16022, ECC 200) is square, from 10 × 10 to 48 × 48 modules, and the smallest symbol that holds the link is used. Both are checked to scan when printed at 203 and 300 dpi, the usual resolutions of thermal label printers. If the link is too long for a size's smallest module, that size prints a notice instead of a code: choose a larger size.

QR code and Data Matrix are two of the data carriers EN 18220 names. Which one a product group needs is set by its own regulation. RFID and NFC tags, print-quality grading of real prints and an IEC 61406 frame around the code are not covered.

Labels exist only for an active link.

## Add product identifiers

Besides its own address, a link can carry identifiers your products already have, such as a GTIN. The link's own token stays its primary identifier.

| Scheme | Identifier |
| --- | --- |
| `gs1_digital_link` | A GTIN (AI 01), optionally with variant (22), lot (10) and serial (21), in that order. The check digit is verified and the GTIN padded to 14 digits. |
| `iec61406` | An `https` identification link. |
| `did` | A decentralized identifier. |
| `doi` | A digital object identifier. |

- **Item or model**: a serial names one item, so it belongs on a thing's link. A lot names a batch, and a GTIN alone or with a variant names a model, so they belong on a thing type's link.
- **One link each**: an identifier belongs to one link of your tenant. You can remove it until the link is first activated. After that it is permanent, because it may be printed.
- **Your GS1 company prefix**: a GS1 identifier resolves only under a GS1 company prefix Nimbit has verified for your tenant. You request the claim, and Nimbit checks your GS1 licence. If a claim is revoked, its identifiers stop resolving at once. A GTIN-8 is never resolved.

IoT Breeze has no screen for identifiers yet. Both steps below go through the platform API, under `/ocb` on the host you open IoT Breeze on, and need the **Passport** update permission, as a user or an API key with that scope; see [Authentication](../api/authentication.mdx).

1. **Claim your GS1 company prefix**, once:

   ```bash
   curl -X POST "https://<host>/ocb/rest/v2/passport/gs1-prefixes" \
     -H "Authorization: Bearer <access-token>" -H "Content-Type: application/json" \
     -d '{ "prefix": "9506000" }'
   ```

   A U.S. UPC company prefix has 6 to 11 digits and adds `"upc": true`. The claim starts as pending. Contact Nimbit support: they check your GS1 licence and verify the claim. Only then do GS1 Digital Links under that prefix resolve.
2. **Register an identifier** on a link:

   ```bash
   curl -X POST "https://<host>/ocb/rest/v2/passport/links/<link-token>/identifiers" \
     -H "Authorization: Bearer <access-token>" -H "Content-Type: application/json" \
     -d '{ "scheme": "gs1_digital_link", "value": "/01/09506000134352/21/ABC123" }'
   ```

   `<link-token>` is the link's token, the part of its address after `/L/`.

## Open a link by its GS1 Digital Link

A GS1 Digital Link on your link address opens the product link, as `/L/<TOKEN>` does:

```
https://<link address>/01/<GTIN>[/22/<variant>][/10/<lot>][/21/<serial>]
```

- **Fallback**: as a GS1 resolver does, IoT Breeze tries the full value first, then without the serial, then without the lot, then without the variant. The most specific link that is active and shows something opens. If none does, the answer is the same "not found" as for an unknown link.
- **Browser or API**: a browser goes to the page. A client whose `Accept` header asks for JSON or the AAS API is sent there.
- **Serial numbers are off by default.** Then every serial opens the model's or batch's link, which reveals nothing about which serials exist. To open each item's own link, a tenant admin switches on **Resolve serial numbers** under **Administration › Tenant Settings › Features › Product links** and confirms with **Turn on**. Anyone can then try serial numbers one after another: if yours are sequential, others can find and count your items' links. Switch it on only if your serials are random, or you accept that. The switch applies only to GS1 identifiers registered through the API under a GS1 company prefix Nimbit has verified for your tenant.
- **Not resolved**: DIDs, DOIs and IEC 61406 links, which resolve through their own infrastructure; GS1 keys other than the GTIN; a GS1 Digital Link under a path prefix. GS1 resolver link sets and link types are not implemented.

The labels print the link's own address, not a GS1 Digital Link.

## Suspend, resume or retire

| Action | Effect |
| --- | --- |
| **Suspend** | The page shows nothing until you select **Resume**. Printed codes keep their address. |
| **Retire** | Final. The link shows nothing, can never be used again, and its printed codes stop working. **Create new link** makes a link with a new address, so you print new codes. |

After you retire a link, the tab keeps showing it as **Retired**, so you can see why printed codes no longer work.

## What visitors see

Visitors see the published fields (label, value and unit), the published documents, and when the page was last updated. They never see the thing's or type's name or id, unpublished or private fields, file paths, or anything else of your tenant.

Every hidden state gets the same "not found" page: an unknown, not yet public, suspended or retired link, a feature switched off, a thing no longer exposed, or nothing published. A visitor cannot tell them apart. Pages are marked for search engines not to index them, and visitors' personal data is not recorded.

## Limits

- **Busy**: when too many requests arrive, visitors see "Too many requests right now" and can try again a moment later.
- **Changes**: publishing, hiding, suspending and retiring take effect at once. A changed value of a published field shows within about a minute.
- **Documents**: up to 50 MB each. PDF, PNG, JPEG and WebP open in the browser. Other types download.
- **One link address per installation.**
- **Logs**: IoT Breeze logs only the first 6 characters of a link's token.
