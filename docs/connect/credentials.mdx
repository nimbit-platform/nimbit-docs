Create the credentials a device uses to connect over MQTT or HTTP, and replace them without downtime. How they are used: [How devices connect](./how-devices-connect.mdx).

## Before you start

- You need the permission to create device credentials on things. Without it the buttons are missing.
- The thing exists and has a thing type. See [Register a thing](../model/register-thing.mdx).

A thing has a **Primary** and a **Secondary** key slot. Having two lets you move devices to the secondary credential, then rotate the primary.

| Tile | Use it when |
| --- | --- |
| **Basic authentication** | The client only supports a username and password. The password does not expire. |
| **JWT authentication** | You want a bearer token that expires. Validity: 30 days, 1, 2, 5 or 7 years, or a number of days you choose. |
| **Device key** | You need to see or rotate the signing key behind both. |

## Steps

### Create basic credentials

1. Open the thing (**Devices › Things**) and go to **Connections**.
2. In the **Nimbit** block, under **Basic authentication**, select **Primary**, then **Generate credentials**.
3. Copy **Username** and **Password**.

### Create a JWT token

1. Under **JWT authentication**, select **Primary**, then **Generate token**.
2. Choose **Expires in**. The hint shows the exact date.
3. Select **Generate token**.
4. Copy **Username**, **Token** and **Expires at**.

:::warning Copy the token now
Anyone who holds the token can act as the device until it expires or the signing key is rotated. The drawer clears when you close it. Select **Generate new token** if you lost it.
:::

### Read the connection details

Select **Connection info**. The **Device connection** drawer shows **Gateway url**, **Username**, **Client id**, the **Telemetry**, **Commands** and **Errors** topics, and the HTTP URLs under **REST**. Every value has a copy button. The **Username** is the same for every credential type.

Port and TLS differ per deployment. Read them in **Gateway url**: `mqtts://` means TLS.

### Rotate the device key

Rotate to cut off credentials you no longer trust, or to replace a lost token.

1. Move your devices to the credential of the other slot.
2. Under **Device key**, select **View key** to check which key is in use, then select **Rotate** on the slot you retire.
3. Confirm. The message **Signing key rotated** appears.

Every basic credential and token signed by that key stops working for new logins and requests. Create new ones afterwards.

## Check that it worked

Connect with the new credential, as in [Send data over MQTT](./mqtt.mdx) or [Send data over HTTP](./http.mdx). The old credential is refused: `401` over HTTP, a refused connection over MQTT.

An MQTT connection that is already open is not closed by a rotation. Disconnect the device to apply it. A token session ends by itself when the token expires.

## If it doesn't work

- **There is no Nimbit block**: the thing type uses another connector, for example Azure IoT Hub. Its block shows its own credentials.
- **The switch is disabled**: your tenant has switched the connector off.
- **The device is refused after a rotation**: it still uses a credential of the rotated key. Generate new credentials and update the device.
- **The username does not match**: use the **Username** of the same thing. A token and a username from different things are refused.
