Everything a device or a gateway needs to know to connect to the IoT Breeze MQTT broker. How to send a message: [Send data over MQTT](./mqtt.mdx). How a gateway sends: [Send data for many devices through one MQTT gateway](../gateways/mqtt-gateway.mdx).

## Broker

| Item | Value |
| --- | --- |
| Address | **Gateway url** in **Connection info**, for example `mqtt://<host>:1883`. |
| Port and TLS | The platform default is port `1883` without TLS. Your deployment can set another port or TLS: `mqtts://` in **Gateway url** means TLS. |
| MQTT version | 3.1.1. |
| QoS | 0 and 1. The broker does not take QoS 2. |
| Max payload | 4 MiB. |

To find your values, open the thing (**Settings › Onboarding › Things**), go to **Connections** and select **Connection info**. The drawer is titled **Device connection**.

## Credentials

| Setting | Value |
| --- | --- |
| Username | **Username** from **Connection info**. It is the base64url encoding of `<tenantId>/<deviceId>` and is the same for every credential type. |
| Password | The basic **Password**, or the JWT **Token**. A password with three parts separated by dots is treated as a token. |

A JWT session ends when the token expires. A basic session has no expiry. Rotating a key stops new logins with the old credential but does not end open connections.

## Client ID

| Rule | Detail |
| --- | --- |
| Required form | `<tenantId>:<deviceId>`, as **Client id** shows it. |
| With a suffix | `<tenantId>:<deviceId>:<suffix>` is also accepted. |
| Empty | Refused. Always send a client ID. |
| Anything else | Refused with `MQTT client id not allowed`. |

Two connections with the same client ID replace each other. Use a suffix when one device runs several clients.

## Topics

| Direction | Topic | Meaning |
| --- | --- | --- |
| Publish | `tenant/<tenantId>/device/<deviceId>/telemetry` | The device sends [messages](./message-format.mdx). |
| Subscribe | `iot/tenant/<tenantId>/device/<deviceId>/cmd/#` | Commands for the device. |
| Subscribe | `iot/tenant/<tenantId>/device/<deviceId>/error` | Messages that were refused, with the reason. |

`<deviceId>` is the thing's internal ID as **Connection info** shows it, not the **Thing Alternate ID** on the thing page.

A device can publish only to its own telemetry topic and subscribe only to its own `cmd` and `error` topics. Anything else is refused.

## Gateways

A gateway connects with its own credential and sends for the things assigned to it. Its values come from the gateway's connection info, not from a thing's.

| Item | Value |
| --- | --- |
| Username | The base64url encoding of `<tenantId>/gateway:<gatewayId>`. |
| Password | The gateway's password, or a gateway token. A gateway token lives at most ten minutes. |
| Client ID | `<tenantId>:gateway:<gatewayId>`, optionally with `:<suffix>`. Device credentials can't take this form. |
| Session | Ends after at most ten minutes. The gateway reconnects with the same credential. This is how a revoked gateway is cut off. |

| Direction | Topic | Meaning |
| --- | --- | --- |
| Publish | `tenant/<tenantId>/gateway/<gatewayId>/device/<thing>/telemetry` | One [message](./message-format.mdx) for one thing. `<thing>` is the thing's ID or alternate ID. |
| Publish | `tenant/<tenantId>/gateway/<gatewayId>/telemetry` | A gateway batch: a JSON array of messages, each naming its thing in `id`. |
| Subscribe | `iot/tenant/<tenantId>/gateway/<gatewayId>/device/+/cmd/#` | Allowed, for commands to things behind the gateway. |
| Subscribe | `iot/tenant/<tenantId>/gateway/<gatewayId>/device/+/error` | Allowed, for refusal notices. |

A gateway credential can't publish on a thing's own `tenant/<tenantId>/device/<deviceId>/telemetry` topic. The broker acknowledges such a publish at QoS 1 but drops it. A message for a thing that is not assigned to the gateway is discarded and counted on the gateway; see [Check gateway health and traffic](../gateways/fleet-health.mdx).

## Delivery

| Topic | Behaviour |
| --- | --- |
| Telemetry | Accepted at QoS 0 or 1. |
| `cmd/#` | Delivered at QoS 0, even on a QoS 1 subscription. A command is not queued for a device that is offline. |
| `error` | A notice for each message refused after it was accepted, such as an unknown thing type. It is best effort. |

A message with invalid JSON, a missing `thingType`, no content, or a `tenant` or `id` that does not match the topic is dropped at the broker side without a notice on `error`.

## Error notice

A notice on `error` is a JSON object:

| Field | Meaning |
| --- | --- |
| `tenant`, `thing`, `thingType` | What the message named. |
| `stage` | The processing step that refused it. |
| `error` | The reason. |
| `source` | Where the message came from. |
| `time` | When it was refused. |
| `message` | The message as tsflux held it. |
