In about 30 minutes you will have one device sending data to IoT Breeze and a dashboard that shows it. You don't need hardware: IoT Breeze can simulate the device.

The order matters. A thing needs a **published** thing type, and credentials belong to a thing. The same steps are in the app as the guide **Get your first device online**: on Home, while your tenant has no things yet.

:::info What you need
A role that may create thing types and things, for example the tenant admin role. For step 6 with a real device: an MQTT or HTTP client.
:::

## 1. Find your way around

Sign in. If your account belongs to more than one tenant, pick the tenant. You land on **Home**.

The menu on the left follows what you do: **Monitoring** to watch, **Settings › Onboarding** to set up devices, **Automation** and **Configuration** for rules and alerts, **Administration** for users and tenant settings. In the header you find **Ask Nimble**, search (Ctrl+K), notifications, the **?** help drawer, theme and language.

## 2. Create a thing type

A thing type describes a kind of device: which values it sends (measures) and which fixed facts it has (properties).

1. Open **Settings › Onboarding › Thing Types** and select **Create Thing Type**.
2. Enter a name, for example `Room sensor`.
3. On the **Schema** tab, add a measure, for example `temperature`, with its unit (°C) and the range you expect.
4. Optionally add a property, for example `room`.
5. Select **Publish**.

:::warning Publish the thing type
Schema changes are a draft until you publish them. Devices only use the published version, so data for an unpublished measure is refused.
:::

## 3. Optional: attach an interface

An interface is a reusable set of capabilities, for example **Temperature sensing**. When a thing type implements an interface, **Smart dashboards** built on that interface show every thing of that type automatically. You can skip this step and add it later.

On the thing type, attach the interface and map its fields to your measures. More in [Interfaces](#) {/* TODO: link to the Onboarding › Interfaces page */}.

## 4. Create a thing

1. Open **Settings › Onboarding › Things** and select **Create thing**.
2. Enter a name, for example `Meeting room 1`.
3. Enter an ID, or select **Generate**. The ID must be unique in your tenant; your device will use it.
4. Select the thing type you published, an organisation and the groups that may see the thing.
5. Save.

## 5. Get credentials

Open the thing and go to the **Connections** tab. Under **Nimbit**, choose how the device signs in:

| Option | Use it when |
| --- | --- |
| Device key | The device can store a long-lived secret. |
| JWT token | You want credentials that expire; you choose the expiry. |
| Basic auth | The client only supports a username and password. |

Then open **Connection info**. It shows everything the device needs: the MQTT host, the **client ID** prefix, the topic to publish telemetry to, the topics to subscribe to for commands and errors, and the HTTP endpoints with example payloads.

## 6. Send data

</TabItem>
<TabItem value="mqtt" label="MQTT">

Connect to the MQTT host from Connection info on port 1883 (8883 with TLS).

- **Client ID:** `<tenantId>:<deviceId>`, exactly as Connection info shows it. Other client IDs are refused.
- **Publish to:** `tenant/<tenantId>/device/<deviceId>/telemetry`
- **Subscribe to** (optional): `…/cmd/#` for commands and `…/error` for refused messages.

```bash
mosquitto_pub -h <mqtt-host> -p 1883 \
  -i "<tenantId>:<deviceId>" \
  -u "<username>" -P "<password>" \
  -t "tenant/<tenantId>/device/<deviceId>/telemetry" \
  -m '{"temperature": 22.5}'
```

<TabItem value="http" label="HTTP">

Send a structured message. Use the full URL from Connection info.

```bash
curl -X POST "<ingest-url>/api/v1/message/structured" \
  -H "Content-Type: application/json" \
  -d '{
    "tenant": "<tenantId>",
    "thingType": "<thing-type-key>",
    "id": "<deviceId>",
    "data": { "temperature": 22.5 }
  }'
```

| Response | Meaning |
| --- | --- |
| 200 | Accepted. |
| 207 | Several messages: each has its own result in the body. |
| 422 | The message doesn't match the thing type, for example an unpublished measure. |
| 503 | Busy; retry after the time in `Retry-After`. |

## 7. See it arrive

Open **Monitoring › Things** and select your thing. The **Overview** shows the last signal and the latest values; **Telemetry** shows history.

:::tip Nothing arrives?
- **"No signal yet":** check host, port and client ID against Connection info.
- **Refused messages:** subscribe to the `…/error` topic; it says why.
- **Measure missing:** publish the thing type (step 2).
:::

## 8. Build your first dashboard

1. Open **Monitoring › Dashboards** and select **New dashboard**.
2. Choose how it finds its things:
   - **Smart dashboard** on an interface: shows every thing that implements it (step 3).
   - A dashboard for **your thing** or its thing type.
3. In edit mode, add a **line chart** for `temperature` and a **gauge** for its current value.
4. Save. To see it when you sign in, assign it to **Home**.
