Define fields once as an interface, attach it to several thing types, and map the fields whose names differ. One [Smart dashboard](../visualize/smart-dashboard.mdx) then covers every thing of those types. For what interfaces are, read [Thing types, things and interfaces](./things-and-types.mdx).

## Before you start

- Your role can edit thing types and interfaces.
- You have a thing type whose fields you want to share, or a published interface to attach. The platform ships one, [Temperature Sensing](./shipped-interfaces.mdx).

## Publish your fields as an interface

Skip this if the interface already exists.

**From fields you already have on a thing type**

1. Open **Settings › Onboarding › Thing Types**, select the thing type and open **Schema › Interfaces**.
2. Select **Move to interface** and tick the published own fields to move.
3. Choose **New interface** to create it from the selection, as **Experimental** with v1 published. Or choose **Existing interface** to publish the selection as the next version of one of your interfaces.
4. Confirm. The thing type pins the new version, so its schema doesn't change.

**From scratch**

1. Open **Settings › Onboarding › Interfaces**, select **New interface**, enter **Display name**, **Name** and **Description** and save.
2. On the interface page, select **Edit schema**, then **Add measure** or **Add property** in the **Measures** and **Properties** panes.
3. Select **Publish v1** in the header, describe the change in **Changelog** and confirm.

## Attach it to another thing type

1. Open the second thing type and its **Schema › Interfaces** pane.
2. Select **Attach interface**, pick the interface under **Attachable interfaces** and select **Attach**. If the type has a **Suggested** card for it, select **Apply**.
3. If the thing type already has own fields with the same names, the button reads **Attach & absorb**. The interface's definition then replaces those own fields. The interface itself doesn't change.

The interface appears under **Attached interfaces**, labeled **Pinned v1**. Its fields are read-only on the thing type.

## Map fields that have other names

If a device sends `temp_c` where the interface says `temperature`, don't rename anything on the device.

1. In the attached interface, open **Field mapping**.
2. In the row of the interface field, open **This type's field** (**Serve temperature from**) and choose the thing type's own field.
3. Check the line **1 served from another field**.

Select **Remove mapping** to undo it, or **Mapped only** to list only the mapped rows.

:::warning Same name, different value
If the thing type also has its own field with the interface field's name, the mapping wins and the own field's value is never read. The row warns you.
:::

## Move a thing type to a newer version

Thing types keep the version they pinned, so a new interface version changes nothing until you update.

1. On the thing type's **Interfaces** pane, look for **v2 available** next to the interface.
2. Select **Compare** to see what differs.
3. Select **Update to v2**. The update is checked for name collisions and applies at once, like a schema change.

To remove an interface from a thing type, select **Detach**. The dialog says how many thing types and things it affects.

## Check that it worked

On each thing type the interface shows **Up to date**. Select **Generate dashboard** to build a Smart dashboard with one widget per field. It lists every current and future thing whose type implements the interface. On the interface page, **Implemented by** lists the thing types.

## If it doesn't work

- **Attach is refused with a name collision**: a field name of the interface is already used on the thing type, for example by another attached interface. Rename the field that collides.
- **The interface isn't under Attachable interfaces**: it has no published version, or it is already attached.
- **A dashboard widget is empty for one thing type**: its field isn't mapped. Add the mapping.
- **Delete is disabled on the interface**: thing types still implement it. Detach it from each, as listed under **Implemented by**.
