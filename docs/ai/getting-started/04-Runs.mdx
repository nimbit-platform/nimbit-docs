## What are Runs?

In the context of machine learning, a **run** represents an individual execution of an experiment. Each run captures the input parameters, the model being trained and the resulting metrics (such as accuracy, loss, or error) after the execution completes.

Runs help you keep track of how each model performs, making it easy to compare different attempts, whether you are testing different datasets, hyperparameters, or models.

:::info
A run is a record of a single experiment execution. It logs key details such as the model’s performance, metrics and parameters used during the training or inference process.
:::

In our system, runs allow you to:

- Track the performance of each model iteration.
- Log and store input parameters and results for future comparison.
- Compare the performance across different models, datasets, or configurations.
- Identify the best-performing models based on specific metrics.

By keeping track of runs, you can systematically improve your models and gain deeper insights into which configurations work best for your use case.

:::tip
Consider tagging your runs with meaningful names or metadata to easily identify and compare them later.
:::

### What You Can Do with Runs

Our system provides a variety of features to manage your machine learning runs. Here’s what you can do:

- **View all runs**: Retrieve a list of all the runs you’ve executed within your experiments. This provides a comprehensive overview of all model attempts.
- **Retrieve runs for a specific experiment**: You can focus on runs within a specific experiment to analyze how different runs performed under similar conditions.

- **Retrieve a run by ID**: Look up the details of a specific run, including its performance metrics, parameters and status, which helps in deeper analysis of a particular execution.

- **Find the best run**: Identify the run with the best performance based on a specific metric. This is useful when optimizing models for a certain goal, such as minimizing error or maximizing accuracy.

:::info
The **best run** feature helps you quickly identify which model configuration performed the best according to a selected metric, such as RMSE or MAPE.
:::

- **Retrieve run results**: You can retrieve the predicted and actual values for a specific run. This helps you see how well the model’s predictions matched the real-world results.

- **Delete a run**: If you no longer need a run, you can delete it to keep your workspace organized.

:::danger
Be careful when deleting runs, as this action is permanent and the run data cannot be recovered once deleted.
:::

### How These Endpoints Work

These features are powered by **endpoints** that allow you to interact with the runs in your system. Through these endpoints, you can:

- Retrieve lists of runs or details of specific runs.
- Track performance metrics and input parameters for each run.
- Compare multiple runs to find the best-performing model.
- Manage run data by creating, updating, or deleting runs as needed.

This structure allows you to have full control over your machine learning experiments, ensuring that every run is logged and that you can easily analyze and improve your models.
