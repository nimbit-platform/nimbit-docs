# Forecasting API Documentation

This project provides endpoints for creating datasets, analyzing time series data, and building and using forecasting models. Below is a step-by-step guide to the main features and an explanation of the key inputs required at each stage.

## 2. Load Dataset

Copy code

The Id identifies which dataset you are loading into the application. This ID is returned when the dataset is created. The dataset will be loaded into a local directory for analysis.

5. Train Forecasting Model
Endpoint:
bash
Copy code
POST /train-forecast
Request Body:
json
Copy code
{
  "experimentId": "11",
  "datasetId": "clzgr3m9f0000ipso1uk1tqt3",
  "device": "cpu",
  "id": "th_ikpq2lSiHyGzslvRF",
  "timeseriesColumn": "time",
  "valueCol": "matstrk_count",
  "freq": "H",
  "hyperparameterId": "clyo2xfkf0003ip9c3sffeh2h",
  "normalizeTs": true,
  "splitRatio": 0.2,
  "rmvOutliers": true,
  "limitDirection": "forward",
  "interpolateMethod": "linear",
  "ignorePreviousRuns": false,
  "ignoreSteps": "",
  "uri": "./pipeline/",
  "forecastHorizon": 200
}
Input Breakdown:
experimentId: A reference to the experiment being conducted, allowing for multiple runs and trials with different datasets or configurations.
datasetId: The unique identifier of the dataset being used for training.
device: The hardware on which the model will be trained, such as "cpu" or "gpu".
id: The ID of the target variable or time series being used.
timeseriesColumn: The column containing the time index of the dataset.
valueCol: The column containing the target value (in this case, "matstrk_count") that will be forecasted.
freq: The frequency of the time series data (e.g., hourly, denoted by "H").
hyperparameterId: The identifier of the hyperparameters used for model training.
normalizeTs: A boolean indicating whether the time series should be normalized before training.
splitRatio: The ratio to split the data into training and validation sets.
rmvOutliers: Whether or not to remove outliers in the data.
limitDirection: Defines the direction to limit the data for the forecast (e.g., "forward").
interpolateMethod: The method used to handle missing data, such as "linear" interpolation.
ignorePreviousRuns: Whether to ignore results from previous training runs.
uri: The location where training artifacts are saved.
forecastHorizon: The number of future time steps for which forecasts will be made.

forecastHorizon: The number of time steps in the future for which predictions are generated.
uri: The path to where forecast results will be saved.
startDataset: The timestamp where forecasting begins in the dataset.
bucket: The time interval for grouping the forecast data.
