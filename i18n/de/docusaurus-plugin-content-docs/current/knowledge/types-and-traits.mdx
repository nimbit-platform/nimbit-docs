Die Bausteine des Datenmodells des Knowledge Graph unter **Knowledge › Datenmodell** (Tabs **Typen**, **Traits**, **Bibliothek**).

## Typen {#types}

| Eigenschaft | Regel |
| --- | --- |
| Name | PascalCase, im Tenant eindeutig, nicht umbenennbar. |
| Besitzer **System** | Wird mit der Plattform ausgeliefert. Schreibgeschützt, aber Sie können ihn mit **Diesen Typ erweitern** ergänzen. **Erweiterung entfernen** nimmt Ihre Ergänzungen wieder weg. |
| Besitzer **Tenant** | Ihrer. Zusammengesetzt aus Traits sowie eigenen Eigenschaften und Beziehungen. |
| Paket-Badge | Der Typ stammt aus einem Bibliothekspaket und ist daran gebunden. |
| Versionen | Ein neuer Typ wird als v1 gespeichert. Jedes weitere Speichern ist eine neue Version. **Versionen** zeigt einen Vergleich der hinzugefügten, im Typ geänderten und nicht mehr deklarierten Felder. |
| Löschen | Abgelehnt, solange der Typ Datensätze hat, ein anderer Typ auf ihn verweist oder ein Mapping ihn verwendet. |

| Feldoption | Wirkung |
| --- | --- |
| **Erforderlich** | Datensätze müssen das Feld tragen. |
| **Indiziert** | Schnelles Filtern. |
| **Volltext** | Über seine Wörter durchsuchbar. |
| **Synonyme** | Kommagetrennte alternative Wörter, pro Sprache, für die Suche und für Ask Nimble. Verfügbar bei Typen und Beziehungen. |

Eine Beziehung hat einen frei wählbaren Namen wie `feedsInto`, einen Zieltyp, eine Beschreibung und Synonyme. Jedes Feld zeigt seine Herkunft: ein Trait, der Systemtyp, ein Paket oder **Von diesem Mandanten ergänzt**.

Einen Typ einzuengen entfernt keine Werte von vorhandenen Datensätzen. Das Feld fällt nur aus dem Typ heraus.

## Systemtypen {#system-types}

| Typ | Ist |
| --- | --- |
| `Thing` | Ein Gerät, von der Plattform repliziert. |
| `ThingType` | Ein Thing-Typ. |
| `Asset` | Ein Standort oder organisatorischer Knoten in Ihrer Anlagenhierarchie (Standort, Halle, Linie), unter dem Equipment platziert wird. |
| `MaintenanceOrder` | Ein Wartungsauftrag. |
| `MaintenanceRule` | Eine aus einem Handbuch extrahierte Wartungsregel. Entsteht durch Extraktion und Prüfung. |
| `Incident` | Ein Vorfall, von der Plattform repliziert. |
| `Document`, `DocumentChunk` | Eine Datei und ihre indizierten Abschnitte. |
| `DocumentAnnotation` | Ein Bereich einer Zeichnung, verknüpft mit dem Thing, das er abbildet. |
| `Object3D` | Ein Teil eines 3D-Modells, verknüpft mit dem Thing, das er darstellt. |
| `Dashboard`, `Canvas` | Visualisierungen. |
| `AclGroup`, `UserAcl` | Gruppen und die Gruppen jedes Benutzers, für den Zugriff verwendet. |
| `MeasureSpecProposal` | Eine aus einem Handbuch vorgeschlagene Spezifikation eines Messwerts (Einheit, Skalierung, Grenzen). |

## Traits {#traits}

| Trait | Gibt einem Datensatz | Hinweise |
| --- | --- | --- |
| **Hierarchical** | `parent`, `root`, `path`: einen Platz im Enthaltenseinsbaum. | Nötig für Standorte und Ebenen. |
| **Describable** | Name, Beschreibung, Übersetzungen, Tags, alternative Namen. | Der Name ist durchsuchbar. |
| **Aliased** | Kennungen, die er in anderen Systemen hat (System, Typ, Wert). | Mappings ordnen eingehende Zeilen per Alias zu. |
| **Governed** | Ob Zugriffskontrolle gilt, plus die Gruppen und Benutzer, die ihn lesen dürfen. | Ein geschützter Datensatz ohne Freigabe kann verborgen sein. |
| **Measured** | Die Messungen, die er bereitstellt, mit Einheiten und Bereichen. | Systemtypen vorbehalten. |
| **Connectivity** | Verbindungsstatus, zuletzt verbunden, zuletzt getrennt. | |
| **Lifecycle** | Aktueller Status und Statusverlauf. | Der Status speichert Ihre eigene Bezeichnung. |
| **Spatial** | Geografische Koordinaten, ein freier Text zum Standort. | |
| **Scheduled** | Geplanter und tatsächlicher Start und Ende. | |
| **Sourced** | Quellsystem, Quell-ID, zuletzt in der Quelle aktualisiert. | |
| **Versioned** | Gültig ab, gültig bis und der Datensatz, den er ablöst. | |
| **Attributed** | Eigene typisierte Schlüssel-Wert-Attribute. | |
| **Extensible** | Vom Tenant definierte eigene Felder. | Nur flache Werte. |
| **Embedded** | Ein Vektor, damit der Datensatz nach Bedeutung gefunden wird. | Standardmäßig aus. |
| **Searchable** | Gesammelte Tags und Kennungen für die Stichwortsuche. | Von der Plattform gefüllt, nicht von Hand. |
| **Imaged** | Bilder, intern oder extern. | |
| **Pending** | Verknüpfungen zu Datensätzen, die bei Ankunft der Daten noch nicht existierten. | Wird durch den Abgleich aufgelöst. |

## Bibliothekspakete {#library-packs}

| Element | Bedeutung |
| --- | --- |
| **Datenmodelle** | Pakete, die Typen installieren. Beim Installieren eines Typs werden auch die Paket-Typen installiert, auf die er verweist. Installierte Typen gehören Ihnen, sind aber an das Paket gebunden. |
| **Integrationen** | Mapping-Vorlagen und Konnektor-Voreinstellungen. Eine Vorlage unter einem Quellnamen zu kopieren ergibt ein Mapping, das Sie ändern können. Beim Anlegen werden nur die Typen installiert, die Ihnen fehlen. |
| **Auf Version … aktualisieren** | Erscheint, wenn ein Paket eine neue Version hat. **Upgrade prüfen** prüft sie zuerst gegen Ihre Typen. Passt sie nicht, ändert sich nichts. |
| **Deinstallieren** | Entfernt die Typen des Pakets. Abgelehnt, solange ein Typ Datensätze hat, ein anderer Typ auf einen verweist oder ein Mapping einen verwendet. Aus Vorlagen erstellte Mappings bleiben. |

Ist die Bibliothek leer, werden mit der Installation keine Pakete ausgeliefert. Plattform-Admins fügen sie hinzu.
