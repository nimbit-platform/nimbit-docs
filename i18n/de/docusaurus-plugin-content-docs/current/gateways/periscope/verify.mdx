Bestätigen Sie, dass jedes Thing, das Periscope angewendet hat, Werte erhält. `periscope verify` fragt den Abfragedienst der Plattform, nbq, und gibt eine Zeile pro Thing aus. In IoT Breeze zeigen die Karte **Datenverkehr** des Gateways und die neuesten Werte jedes Things dasselbe.

## Voraussetzungen {#before-you-start}

- Periscope hat Things angewendet und streamt seit einigen Minuten.
- Für `periscope verify`: `[ocb] url` ist mit Servicekonto-Zugangsdaten gesetzt, oder Sie übergeben `-nbq-url`. Der Befehl liest das State-Verzeichnis und fragt nbq mit dem Token des Agents.
- Bei einem Gateway prüfen Sie stattdessen in IoT Breeze, wie im nächsten Abschnitt.

## Schritte {#steps}

1. Führen Sie den Befehl mit einem Fenster aus, das die Zeit seit dem Start des Streamings abdeckt:

   ```sh
   periscope verify -config /etc/periscope/periscope.toml -since 5m
   ```

   `-since` ist standardmäßig `5m`. `-nbq-url http://nbq:8100` fragt nbq direkt, aus dem Netz der Plattform heraus.

2. Lesen Sie die Tabelle:

   ```text
   window 2026-10-22T09:55:00Z .. 2026-10-22T10:00:00Z (UTC)

   THING                          TYPE      RECEIVED  MEASURES  VALUES  LATEST (UTC)          PROBLEM
   werk1-Pressing-Line1-Pump1     PumpType  yes       4/4       100     2026-10-22T09:59:58Z  -
   werk1-Pressing-Line1-Pump2     PumpType  yes       3/4       75      2026-10-22T09:59:58Z  missing: running
   werk1-Baking-Line2-Oven1       Oven1_…   NO        0/4       0       -                     nothing received (…)

   2/3 things received data, 5 measures never seen in the window, 0 unmapped metrics since 2026-10-22T09:00:12Z
   ```

   | Spalte | Bedeutung |
   | --- | --- |
   | `RECEIVED` | Ob das Thing im Fenster irgendeinen Wert hatte. |
   | `MEASURES` | Gesehene Messwerte, von den für das Thing zugeordneten. |
   | `VALUES` | Im Fenster gespeicherte Werte. |
   | `LATEST (UTC)` | Zeit der neuesten Zeile des Things. |
   | `PROBLEM` | Was fehlt oder warum nichts ankam. |

3. Prüfen Sie den Exit-Code:

   | Exit | Bedeutung |
   | --- | --- |
   | 0 | Jedes angewendete Thing hat Werte erhalten, und kein Wert liegt in der Zukunft. |
   | 1 | Ein angewendetes Thing hat nichts erhalten, ein neuester Wert liegt in der Zukunft (mehr als eine Minute vor der Uhr der Box) oder es ist noch nichts angewendet. |
   | 2 | nbq konnte nicht gefragt werden. Nichts wurde geprüft. |

4. Öffnen Sie in IoT Breeze **Geräte › Gateways**, öffnen Sie das Gateway und lesen Sie **Letzte Daten** und **Aktive Things** auf der Karte **Datenverkehr**. Öffnen Sie eines seiner Things, um die neuesten Werte zu sehen. Siehe [Zustand und Datenverkehr von Gateways prüfen](../fleet-health.mdx).

## Prüfen, ob es geklappt hat {#check-that-it-worked}

`periscope verify` endet mit Exit 0 und `N/N things received data`. In IoT Breeze ist das Gateway **Online**, **Aktive Things** entspricht der Zahl der angewendeten Things, und **Verworfen pro Minute** ist 0.

## Wenn es nicht klappt {#if-it-doesnt-work}

- **Exit 2**: nbq konnte nicht gefragt werden, zum Beispiel wegen eines Verbindungsfehlers, eines Timeouts oder eines `401`. Prüfen Sie die Verbindung zur Plattform oder übergeben Sie `-nbq-url`.
- **Alles zeigt `nothing received` mit `provisioner = "tsflux"`**: nbq sucht Things über die Plattform-ID, und dieser Provisioner hat noch keine. Das ist zu erwarten, bis der Provisioner `ocb` gelaufen ist.
- **Ein Wert liegt in der Zukunft, oder aus einer Quelle in Ortszeit kommt nichts an**: Die Quelle sendet Ortszeit, als UTC gekennzeichnet. Östlich von Greenwich landen die Werte in der Zukunft, westlich davon in der Vergangenheit, wo das Thing als „nichts empfangen“ erscheint. Korrigieren Sie Uhr oder Zeitzone der Quelle. Für MQTT setzen Sie `timezone`.
- **Ein Thing fehlt in der Tabelle**: Es werden nur angewendete Things geprüft. Bestätigen und wenden Sie es zuerst an. Siehe [Periscope-Erkennungen freigeben](./approve-discoveries.mdx).
- **`unmapped metrics` ist größer als 0**: Die Zusammenfassung nennt die häufigste nicht zugeordnete Adresse. Bestätigen Sie ihren Vorschlag.
