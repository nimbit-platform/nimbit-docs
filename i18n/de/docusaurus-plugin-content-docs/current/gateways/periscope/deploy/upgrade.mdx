Upgrade enrolled boxes to a Periscope version that uses the gateway's namespace and the gateway's own data credential. The order matters: boxes first, then the tenant key.

## Before you start

- The platform runs a release that has gateways, `gateways.me` and the gateway credential. A box on an older platform keeps working with the tenant credential, warns once, and asks for the gateway credential again at its next start.
- You can change the box's image or binary, and rotate the tenant key in IoT Breeze.
- Start with one box. Upgrade the others when it is **Online** and its things receive values.

## Steps

1. Back up the box's [state directory](./state-and-backup.mdx).
2. Replace the software and keep the state.
   - Container: pull the new image, remove the container and run it again with the same volume, as in [Run Periscope in a container](./run-in-a-container.mdx). The state stays in the volume.
   - Service: replace `/usr/local/bin/periscope` and run `sudo systemctl restart periscope`.
3. Check the version and the file:

   ```sh
   periscope version
   periscope validate -config /etc/periscope/periscope.toml -offline
   ```

4. Upgrade every other box the same way.
5. When all boxes run the new version, rotate the tenant key, both slots. {/* TODO(product): where in IoT Breeze does a tenant admin rotate the tenant key, and who may? */} A tenant credential that a box cached before the upgrade then stops working.
6. If you also run MQTT device gateways, issue them new credentials. The rotation ends every MQTT gateway's credential.

## What changes on a box

| Change | Effect |
| --- | --- |
| The namespace replaces `agent.name` in alternate IDs | On its first start, the box asks `gateways.me`. Its next discovery proposes its things again under the namespace. In `zero-touch` mode they are created at once, in `confirm` mode they wait for you. The old things stay with a reason. Nothing is renamed or deleted. |
| The gateway credential | The outputs ask for the gateway's own credential. The MQTT client ID becomes `<tenant>:gateway:<gateway id>:<suffix>` and the topics start with `tenant/<tenant>/gateway/<gateway id>/`. |
| Ingest tokens | HTTP and stream ingest use a token of at most 10 minutes. A revoked gateway stops within one token lifetime. |
| Health interval | `agent.health_interval` is at most `5m`. A longer value is refused. |

A box on the old version that has no cached credential, such as a new box or one with a reset state, gets none: the platform refuses a gateway's token the tenant credential. That is why you upgrade the boxes first. See [Outputs reference](../outputs.mdx#the-gateway-credential).

If `agent.name` already equals the gateway's namespace, the alternate IDs don't change and no thing is proposed twice.

## Clean up the old things

After the first discovery under the namespace, the old things remain, with the data they already hold. Reassign or delete them in IoT Breeze. New values go to the things under the namespace. A new thing whose name is taken by an old one is created as `<name> (<namespace>)`.

## Check that it worked

The gateway is **Online**, its **Traffic** card shows **Messages per minute** above zero and **Discards per minute** at 0, and `periscope verify -since 5m` exits 0. See [Verify that data arrived](../verify.mdx).

## If it doesn't work

- **The agent logs that the namespace is not known yet**: the platform hasn't answered `gateways.me`. The box discovers nothing until it does.
- **`agent.health_interval` is refused**: set it to `5m` or less.
- **The broker refuses the connection, or topics are refused**: a custom `topic` in `nimbit_mqtt` must start with `tenant/{tenant}/gateway/{gateway}/`, or be removed. See [Troubleshoot Periscope](../troubleshooting.mdx).
- **The platform answers `403 GATEWAY_SCOPE_REQUIRED`**: an old version asked a gateway for the tenant credential. Upgrade the box.
