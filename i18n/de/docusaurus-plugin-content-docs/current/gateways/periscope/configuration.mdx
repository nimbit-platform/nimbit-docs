Periscope liest eine TOML-Datei: `-config`, sonst `$PERISCOPE_CONFIG`, sonst `periscope.toml` im Arbeitsverzeichnis. Der Agent liefert seine vollständige Dokumentation, einschließlich jedes Plugin-Schlüssels, unter `http://<listen>/ui/docs` mit Suche aus. Sie ist im Binary enthalten, Sie können sie also an der Edge-Box ohne Internetzugang lesen.

## Dateiregeln {#file-rules}

- `${NAME}` in einem String-Wert wird durch die Umgebungsvariable `NAME` ersetzt, leer, wenn sie nicht gesetzt ist. Nur String-Werte werden expandiert, nie Schlüssel. Ein Wert mit Anführungszeichen, Backslash oder Zeilenumbruch wird abgelehnt.
- Unbekannte Schlüssel sind überall Fehler. `periscope validate` gibt den aufgelösten Plan ohne Geheimnisse aus.
- Dauern sind Strings in Go-Form: `"500ms"`, `"1s"`, `"1h"`. Eine bloße Zahl wird abgelehnt.
- Ein Schlüssel, der eine Datei benennt, muss eine reguläre Datei von höchstens 16 MiB (Tag-Dateien, Registertabellen, Importe) oder 1 MiB (Konfigurationen, Zuordnungen) benennen. Relative Pfade werden gegen das Verzeichnis der Konfigurationsdatei aufgelöst.
- Der Einrichtungsbildschirm der Web-Oberfläche schreibt in `periscope.toml`, wenn sie beschreibbar ist, sonst in das Overlay `state_dir/config.ui.toml`. `periscope.toml` gewinnt Schlüssel für Schlüssel.

## `[agent]` {#agent}

| Schlüssel | Vorgabe | Bedeutung |
| --- | --- | --- |
| `name` | erforderlich | Connector-Name, `A-Za-z0-9_-`, 1 bis 64 Zeichen. Steht vor jeder Alternate-ID, außer bei einem Gateway, wo der Namespace davorsteht. Dient als Suffix der MQTT-Client-ID. |
| `state_dir` | `/var/lib/periscope` | Wo der Agent seinen Zustand ablegt. Angelegt mit Modus 0700, Dateien 0600. |
| `interval` | `1s` | Flush-Intervall des Batchers: Ausstehende Werte werden mindestens so oft geschrieben. |
| `max_batch` | `100` | Ein Thing wird bei dieser Zahl ausstehender Werte vorzeitig geflusht. |
| `discovery_interval` | `1h` | `serve`: wie oft neu erkannt und angewendet wird. |
| `log_level` | `info` | `debug`, `info`, `warn` oder `error`. |
| `log_encoding` | `json` | `json` oder `console`. |
| `dry_run` | `false` | Im Probelauf starten: Nichts wird an die Plattform geschrieben, und kein Ausgang sendet. Der Plan bleibt in `plan.json`. |
| `watch_config` | `true` | `serve`: neu laden, wenn sich `periscope.toml` oder das Overlay ändert. |
| `health_interval` | `5m` | Nur Gateway: wie oft die Zustandsmeldung gesendet wird. von `1m` bis `5m`. Ein längeres Intervall wird abgelehnt: Das Gateway-Thing geht nach 15 Minuten ohne Meldung auf Offline und würde sonst flackern. Eine Änderung gilt ab der nächsten Meldung. |

Die Alternate-ID jedes Things beginnt mit `agent.name` – auf einem Gateway mit dem Namespace des Gateways – und kann den eigenen `mount` eines Eingangs enthalten. Eine Änderung legt neue Things an und benennt alte nie um. Wählen Sie sie vor dem ersten Anwenden.

## `[ocb]` {#ocb}

Die Verbindung zur Plattform. Mit einer `url` ist genau eine Zugangsdaten-Art erforderlich.

| Schlüssel | Vorgabe | Bedeutung |
| --- | --- | --- |
| `url` | leer | Die Basis-URL der Plattform, etwa `https://nimbit.example.com`. |
| `path_prefix` | `/ocb` | Zwischen `url` und `/rest/...`. Verwenden Sie `""`, wenn `url` direkt auf das Backend zeigt. |
| `gateway` | `false` | Als das Gateway anmelden, das `periscope enroll -code` eingerichtet hat: eigener Schlüssel in `state_dir`, kein Passwort. Siehe unten. |
| `email` | leer | Servicekonto-Modus: ein Benutzer Ihrer Organisation. |
| `password` | leer | Das Passwort des Servicekontos, optional. Ohne es speichert `periscope enroll` eine Refresh-Sitzung. Ein Passwort ohne `email` wird abgelehnt. |
| `token` | leer | Ein Bearer-Token, unverändert verwendet und nie erneuert. Für Tests. |
| `timeout` | `30s` | Pro Anfrage. |
| `mode` | `confirm` | `confirm`: Vorschläge warten auf eine Person. `zero-touch`: alles Vorgeschlagene wird angewendet. |
| `mount` | leer | Pfadpräfix für alles, was dieser Agent erkennt, etwa `lenneform/werk-altena`. |
| `levels` | `[]` | Namen für die Platzierungselemente, etwa `["site", "area", "line"]`. Kleinbuchstaben `a-z`, `0-9`, `_`. |
| `features_ttl` | `10m` | Wie lange die Features der Organisation zwischengespeichert werden. |
| `provisioner` | `ocb`, wenn `url` gesetzt ist, sonst `file` | Siehe die Tabelle unten. |
| `allow_insecure` | `false` | `http://` zu einem Host akzeptieren, der nicht Loopback ist, für `url`, `[auth] url` und `[contexus] url`. Zugangsdaten gehen dann im Klartext über die Leitung. |

`gateway = true` bedeutet:

- Der Agent meldet sich mit einem eigenen Schlüsselpaar und ohne Passwort an. Sein Token gilt 5 Minuten und nur für das Plattform-Backend. Der Schlüssel ist ein Jahr gültig, und der Agent registriert den nächsten 30 Tage vor Ablauf selbstständig.
- Der Namespace des Gateways steht statt `agent.name` vor jeder Alternate-ID: `<namespace>/<address>` oder `<namespace>/<input mount>/<address>`. `enroll` liest den Namespace und behält ihn in `gateway.json`. Bis die Plattform geantwortet hat, erkennt und wendet der Agent nichts an und fragt jede Minute erneut. Eine Plattform ohne die Route `gateways.me` behält `agent.name` als Präfix.
- Der Agent sendet alle `agent.health_interval` eine Zustandsmeldung.
- Die Plattform-Ausgänge veröffentlichen mit den eigenen Zugangsdaten des Gateways auf den Topics des Gateways. Siehe [Ausgänge-Referenz](./outputs.mdx#the-gateway-credential).
- Eine Datei, die zusätzlich `email`, `password` oder `token` setzt, wird abgelehnt: Es ist genau eine Zugangsart erlaubt.
- `require_input = false` beim Prozessor `heartbeat` wird abgelehnt.
- Die Platzierung in Contexus ist aus, weil das Token nur für das Backend gilt.

Einfaches HTTP wird nur zu einem Loopback-Host akzeptiert, außer bei `allow_insecure = true`.

### Provisioner {#provisioners}

| Provisioner | „Anwenden“ tut | Verwenden, wenn |
| --- | --- | --- |
| `ocb` | Legt Thing-Typen und Things mit Namen, Einheiten, `path`, Ebenen und `sourcePath` an und erweitert sie. | Der Normalfall: Die Plattform hat saubere Namen, bevor der erste Wert eintrifft. |
| `tsflux` | Schreibt nichts in die Plattform. Markiert Vorschläge als angewendet und schreibt die Zuordnung. | Daten fließen müssen, bevor jemand Things benennt. Die Plattform legt unbekannte Things beim Schreiben an, ohne Einheiten oder Pfade. `periscope verify` liest dann jedes Thing als „nichts empfangen“, bis der Provisioner `ocb` gelaufen ist. |
| `file` | Schreibt in `provisioned-file.json`. | Tests und Offline-Versuche. |

### Platzierung {#placement}

Der `path` eines Things ist `mount` plus sein Knotenpfad, mit `/` verbunden. Die Ebenen benennen diese Elemente, beginnend beim letzten Element des Mounts. Mit `mount = "lenneform/werk-altena"`, `levels = ["site", "area", "line"]` und einer Presse unter `Pressing/Line1/Press 1` erhält die Presse `site = werk-altena`, `area = Pressing`, `line = Line1`. Jede Ebene wird zu einer Eigenschaft des Thing-Typs, die auch ein Serien-Tag ist.

Ein Mount besteht aus Pfadelementen, mit `/` verbunden: kein leeres Element, kein `.` oder `..`, kein Leerzeichen um ein Element, kein Steuerzeichen. Ein Eingang kann einen eigenen `mount` setzen.

## `[auth]` {#auth}

Das Identitätsverzeichnis der Plattform, verwendet für das Servicekonto und die Anmeldung an der Web-Oberfläche.

| Schlüssel | Vorgabe | Bedeutung |
| --- | --- | --- |
| `url` | `ocb.url`, wenn `ocb.path_prefix` nicht leer ist | Wo die Token-API des Verzeichnisses antwortet. |

Der Proxy der Plattform leitet die Token-API nur über `https://`. Für eine Plattform mit einfachem HTTP setzen Sie `[auth] url` auf die eigene Adresse des Verzeichnisses, etwa `http://identity-directory:8300`.

## `[contexus]` {#contexus}

Nach dem Anwenden kann Periscope die Platzierung der angewendeten Things an Contexus senden.

| Schlüssel | Vorgabe | Bedeutung |
| --- | --- | --- |
| `url` | `ocb.url` + `/contexus`, wenn `path_prefix` gesetzt ist | Basis-URL ohne `/v1`. Leer: Es wird nichts gesendet. |
| `source` | `periscope` | Basisname der beiden Staging-Quellen: `<source>-assets` und `<source>-things`. |
| `timeout` | `30s` | Pro Anfrage. |
| `enabled` | nicht gesetzt | Nicht gesetzt folgt dem Contexus-Feature der Organisation. `false` sendet nie. `true` sendet immer. |

Ein Contexus-Fehler lässt ein Anwenden nie scheitern.

## `[server]` {#server}

| Schlüssel | Vorgabe | Bedeutung |
| --- | --- | --- |
| `listen` | `127.0.0.1:8400` oder `PERISCOPE_LISTEN` | Probes, `/version`, die Erkennungs- und `/api/v1`-API und die Web-Oberfläche. Das Image setzt `0.0.0.0:8400`. Außerhalb von Loopback ohne `token` oder `[server.auth]` sind Lesezugriffe im Netz offen, und der Agent warnt. |
| `internal_listen` | `127.0.0.1:<listen port + 1>` | `/metrics` und `/debug/*`. |
| `token` | leer | Bearer-Token für `/snapshot`, `/proposals` und `/api/v1/*`. Ohne es sind Lesezugriffe offen und Schreibzugriffe abgelehnt. |
| `trusted_proxies` | `[]` | Reverse Proxies, deren `X-Forwarded-For` den Client nennt. |
| `ui` | `true` | Die Web-Oberfläche unter `/ui` bereitstellen. |

`[server.tls]` schaltet HTTPS ein, auch leer. Ohne `cert_file` und `key_file` erzeugt es ein selbstsigniertes Zertifikat in `state_dir`. Schlüssel: `cert_file`, `key_file`, `hsts`. Das Paar wird ohne Neustart neu geladen.

`[server.auth]` lässt Personen sich mit ihrem Plattformkonto an der Oberfläche anmelden. Tenant-Admins ändern Dinge, alle anderen in der Organisation lesen.

| Schlüssel | Vorgabe | Bedeutung |
| --- | --- | --- |
| `url` | `[auth] url` | Die Basis-URL des Identitätsverzeichnisses. |
| `cell` | erforderlich | Der Name der Plattform-Zelle, zur Prüfung von Tokens verwendet. Fragen Sie Ihren Plattformadministrator. |
| `admin_roles` | `["admin"]` | Rollen, die etwas ändern dürfen. Wird exakt verglichen. |
| `session_ttl` | `12h` | Eine Sitzung endet so lange nach der Anmeldung. |
| `issuer` | Der der Zelle | Das `iss` des Tokens. |
| `basic_cache` | `5m` | Wie lange die Basic-Anmeldung eines Skripts gemerkt wird. |
| `allow_insecure` | `false` | `http://` zu einem Host akzeptieren, der nicht Loopback ist. |

## Plugins {#plugins}

Jede Plugin-Instanz ist eine Tabelle in einem Array: `[[inputs.<name>]]`, `[[processors.<name>]]` oder `[[outputs.<name>]]`. Jede Tabelle akzeptiert `alias`, den Namen der Instanz: 1 bis 64 Zeichen aus `A-Za-z0-9_.-`, beginnend mit einem Buchstaben oder einer Ziffer. Jeder Eingang akzeptiert auch `mount`. Prozessoren laufen in der Reihenfolge der Datei. Benennen Sie den Alias eines Eingangs nach einem Anwenden um, löst sich seine Zuordnung ab.

## Neu laden {#reloading}

`serve` übernimmt eine geänderte Konfiguration ohne Neustart. Drei Auslöser teilen sich einen Weg: SIGHUP, die Dateiüberwachung (`agent.watch_config`) und `POST /api/v1/agent/reload` oder die Schaltfläche **Reload** auf der Seite **Config** der Oberfläche.

Ein Neuladen wird zuerst validiert. Eine Konfiguration, die nicht lädt, hält den Agent nie an: Er läuft mit der letzten guten weiter, protokolliert den Fehler und zeigt ihn auf der **Overview**. Nur die Plugin-Instanzen, deren Einstellungen sich geändert haben, starten neu. Ein Ausgang, der neu startet, verliert nichts, weil seine Warteschlange geschlossen wird und die neue Instanz sendet, was sie hält. Eine Änderung unter `[ocb]`, auch an `gateway`, startet jeden Ausgang neu, der dann die passenden Zugangsdaten anfordert.

Diese Schlüssel gelten erst beim nächsten Start, und die **Overview** zeigt `restart required`, bis die Datei dem laufenden Wert entspricht:

`agent.name`, `agent.state_dir`, `agent.log_level`, `agent.log_encoding`, `server.listen`, `server.internal_listen`, `server.token`, `server.ui`, `server.trusted_proxies`, `[server.auth]` und die Pfade in `[server.tls]`.

## State-Verzeichnis {#state-directory}

Alles, was der Agent aufbewahrt, liegt in `agent.state_dir`. Sichern Sie es: Es enthält die Identität des Agents gegenüber der Plattform.

| Datei | Enthält | Löschen unbedenklich |
| --- | --- | --- |
| `snapshot-<input>.json` | Die letzte Erkennung jedes Eingangs. | Ja. |
| `proposals.yaml` | Thing-Typen und Things mit ihrem Status. | Nur, um von vorn zu beginnen. |
| `edits.yaml` | Umbenennungen, Zusammenführungen, Einheiten und Skalierungen aus der Oberfläche. | Um zu den erkannten Namen zurückzukehren. |
| `mapping.json` | Adresse zu Thing, Thing-Typ und Messwert. | Das nächste Anwenden baut sie neu auf. |
| `apply-log.jsonl` | Eine Zeile pro angewendetem, übersprungenem oder fehlgeschlagenem Element. | Es ist ein Audit-Trail. |
| `gateway_key.pem`, `gateway.json` | Der Schlüssel eines Gateways und seine IDs, Namespace, Gateway-Thing und Endpunkte. | Nur mit einem neuen Onboarding-Code. |
| `gateway_key.next.pem` | Der nächste Schlüssel, solange eine Rotation ihn registriert. | Nicht, solange eine Rotation läuft. |
| `tenant.json` | Die Organisation, an die dieser State gebunden ist. | Nur, um sich mit einer anderen Organisation zu verbinden. |
| `nimbit-gateway-credential.json` | Die zwischengespeicherten Datenzugangsdaten eines Gateways. | Ja. Neue werden angefordert. |
| `nimbit-mqtt-credential.json` | Die zwischengespeicherten Tenant-Zugangsdaten einer Servicekonto-Box. | Ja. Neue werden angefordert. |
| `setup-code.json` | Der Hash des einmaligen Codes des Einrichtungsbildschirms. | Ja. |
| `enrollment.json` | Die Sitzung des Servicekontos. | `periscope enroll -revoke` beendet sie. |
| `config.ui.toml` | Das vom Einrichtungsbildschirm geschriebene Overlay. | Der Agent verliert dann beim nächsten Neuladen die Verbindung. |
| `tsflux-stream/<output>/` | Die Platten-Warteschlange des Stream-Ausgangs. | Verliert noch nicht gesendete Werte. |
| `spool/<output>/` | Der Platten-Spool von `tsflux` und `nimbit_mqtt`. | Verliert noch nicht gesendete Werte. |
| `opcua-<input>.crt`, `.key`, `.pin` | Das OPC-UA-Client-Zertifikat und das angeheftete Serverzertifikat. | Nur wenn der Server einem neuen vertrauen soll. |
| `ui.db` | Die Sitzungen und das Audit-Log der Oberfläche. | Beendet jede Sitzung. |
