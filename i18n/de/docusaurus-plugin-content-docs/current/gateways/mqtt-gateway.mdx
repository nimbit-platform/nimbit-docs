Verbinden Sie ein Gerät, das MQTT spricht, etwa einen eWON Flexy, mit einer Zugangsberechtigung für das Gateway und senden Sie darüber Daten für mehrere Things. Wie Zugehörigkeit und Scope funktionieren, steht unter [Wie Gateways funktionieren](./how-gateways-work.mdx).

## Voraussetzungen {#before-you-start}

- Sie brauchen die Berechtigung **Gateway** (die eingebaute Rolle **Administrator** hat sie).
- Das Gerät kann sich mit MQTT 3.1.1, Benutzername und Passwort und einer Client-ID Ihrer Wahl verbinden. Der Broker akzeptiert QoS 0 und 1, nicht 2.
- Jedes Gerät hinter dem Gateway ist ein Thing Ihrer Organisation, oder Sie können es jetzt [registrieren](../model/register-thing.mdx). Sein Thing-Typ hat die Messwerte, die Sie senden werden.

## Das Gateway hinzufügen {#add-the-gateway}

1. Öffnen Sie **Einstellungen › Onboarding › Gateways** und wählen Sie **Gateway hinzufügen**.
2. Wählen Sie unter **Typ** die Option **MQTT-Gerät**.
3. Geben Sie einen **Namen** ein. Lassen Sie **Namespace** leer oder geben Sie einen ein.
4. Wählen Sie unter **Format der Konfigurationsdatei** die Option **Umgebungsdatei (.env)**, **JSON (.json)** oder **eWON-Flexy-BASIC-Parameter (.bas)**. Die Zugangsdaten sind in jedem Format gleich.
5. Wählen Sie **Gateway hinzufügen**.

IoT Breeze zeigt **MQTT-Zugangsdaten für** den Namen des Gateways. Kopieren Sie jetzt das **Passwort** oder wählen Sie **Konfiguration herunterladen**. Das Passwort wird nur einmal angezeigt; eine Datei, die Sie später herunterladen, enthält stattdessen einen Platzhalter.

Das Ergebnis listet diese Zeilen. Kopieren Sie sie vom Bildschirm, statt sie von Hand zu bauen.

| Zeile | Verwendung |
| --- | --- |
| **Host**, **Port**, **TLS** | Der Broker. **An (mqtts)** heißt, der Listener verlangt TLS. |
| **Benutzername**, **Passwort** | Die Zugangsdaten. |
| **Client-ID-Präfix** | `<tenant>:gateway:<gateway id>`. Verwenden Sie es als Client-ID oder hängen Sie `:<suffix>` an. Der Broker lehnt jede andere Client-ID ab. |
| **Topic-Präfix** | Jedes Topic, auf dem Sie veröffentlichen, beginnt damit. |
| **Telemetrie-Topic** | Veröffentlichen Sie hier die Daten eines Things. |
| **Batch-Topic** | Veröffentlichen Sie hier ein Array mit Daten mehrerer Things. |
| **Status-Topic** | Veröffentlichen Sie hier den eigenen Zustand des Gateways. |

Bei einem eWON Flexy enthält die **.bas**-Datei diese Werte als BASIC-Parameter. Das BASIC-Programm, das sie liest und Ihre Tags veröffentlicht, erhalten Sie auf Anfrage beim NimBit-Support unter [info@nimbit.de](mailto:info@nimbit.de).

## Things dem Gateway zuordnen {#put-things-on-the-gateway}

Ein Gateway kann nur für Things senden, die ihm gehören, und seine Nachrichten legen nie Things an.

1. Legen Sie die Things in IoT Breeze an, falls sie nicht existieren.
2. Öffnen Sie das Gateway, wählen Sie den Tab **Things** und dann **Things zuordnen**. Suchen Sie die Things und wählen Sie **Zuordnen**. Oder öffnen Sie ein Thing, bearbeiten Sie es und wählen Sie unter **Gateway** das Gateway.

Ein Thing gehört zu höchstens einem Gateway. Wenn Sie ein Thing zuordnen, das an einem anderen Gateway hängt, wechselt es.

## Daten veröffentlichen {#publish-data}

Verbinden Sie sich mit den Zugangsdaten und veröffentlichen Sie JSON.

<Tabs groupId="gateway-publish">
<TabItem value="thing" label="Ein Thing pro Nachricht" default>

Veröffentlichen Sie auf dem **Telemetrie-Topic** und ersetzen Sie `<thing>` durch die ID oder Alternate-ID des Things:

```text
tenant/<tenant>/gateway/<gateway id>/device/<thing>/telemetry
```

```json
{
  "thingType": "pump",
  "time": "2026-11-06T10:15:00Z",
  "data": { "pressure": 4.18, "running": true }
}
```

</TabItem>
<TabItem value="batch" label="Ein Batch für mehrere Things">

Veröffentlichen Sie auf dem **Batch-Topic** ein Array mit einem Element pro Thing. Jedes Element nennt sein Thing mit `id`:

```text
tenant/<tenant>/gateway/<gateway id>/telemetry
```

```json
[
  { "id": "pump-1", "thingType": "pump", "time": "2026-11-06T10:15:00Z", "data": { "pressure": 4.18 } },
  { "id": "tank-3", "thingType": "tank", "data": { "level": 0.62 } }
]
```

Ein Batch kann 500 Elemente und 1 MiB enthalten. Eine größere Veröffentlichung wird ganz verworfen. Ein fehlerhaftes Element wird einzeln verworfen. Lassen Sie ein Gerät weg, das Sie nicht erreichen, statt seine letzten Werte erneut zu senden: Jedes gespeicherte Element hält sein eigenes Thing online.

</TabItem>
</Tabs>

`thingType` ist der Name oder die ID des Thing-Typs. Lassen Sie `time` weg, um die Ankunftszeit zu verwenden. Messwertnamen und die vollständigen Nachrichtenregeln stehen unter [Nachrichtenformat](../connect/message-format.mdx).

Veröffentlichen Sie alle 5 Minuten den eigenen Zustand des Gateways auf dem **Status-Topic**:

```json
{
  "thingType": "mqtt_gateway",
  "time": "2026-11-06T10:15:00Z",
  "data": { "uptime_s": 5400, "buffer_used_pct": 0, "buffer_oldest_s": 0, "errors_per_min": 0, "clock_offset_ms": 0 }
}
```

Das Gateway wird mit der ersten Nachricht **Online** und nach drei ausgebliebenen **Offline**.

## Prüfen, ob es geklappt hat {#check-that-it-worked}

Öffnen Sie das Gateway. Der Tab **Zustand** zeigt **Online**, und die Karte **Datenverkehr** zeigt **Nachrichten pro Minute** und **Aktive Things**, ein bis zwei Minuten nach den ersten Daten. Öffnen Sie eines der Things: Seine neuesten Werte sind da.

## Wenn es nicht klappt {#if-it-doesnt-work}

- **Der Broker lehnt die Verbindung ab**: Prüfen Sie die Client-ID gegen das **Client-ID-Präfix** und ob Sie das Passwort vollständig kopiert haben. Verloren? Wählen Sie im Zeilenmenü **Neue Zugangsdaten**; die alten Zugangsdaten funktionieren für neue Verbindungen sofort nicht mehr.
- **Eine Veröffentlichung wird bestätigt, aber nichts wird gespeichert**: Das Topic liegt außerhalb des **Topic-Präfix** des Gateways. Der Broker bestätigt eine QoS-1-Veröffentlichung, die er danach verwirft.
- **Der Datenverkehr zeigt Verworfenes**: **Verworfen pro Minute** nennt die Gründe. `not_member` heißt, das Thing ist diesem Gateway nicht zugeordnet. `unknown_thing` heißt, das Thing oder sein Thing-Typ existiert nicht. `id_missing` heißt, ein Batch-Element hat keine `id`.
- **Das Gateway bleibt Offline, obwohl Daten ankommen**: Nur seine eigene Zustandsmeldung setzt es auf online. Veröffentlichen Sie auf dem **Status-Topic**.
