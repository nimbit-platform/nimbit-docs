Nachschlagetabellen für Gateways. Das Modell erklärt [Wie Gateways funktionieren](./how-gateways-work.mdx).

## Gateway-Typen {#gateway-types}

| Typ | Identität | Braucht | Eigener Thing-Typ |
| --- | --- | --- | --- |
| **Periscope** | Schlüsselpaar, bei der Registrierung hinterlegt | Einen einmaligen Onboarding-Code | `periscope_gateway` |
| **MQTT-Gerät** | Broker-Benutzername und -Passwort | Eine Konfigurationsdatei oder die angezeigten Zugangsdaten | `mqtt_gateway` |

Jedes Gateway hat ein eigenes Thing mit der Alternate-ID `gateway-<id>`. Es wird mit dem Gateway angelegt und bleibt bei ihm.

## Felder {#fields}

| Feld | Gilt für | Regeln |
| --- | --- | --- |
| **Name** | Beide | 1 bis 100 Zeichen, eindeutig in der Organisation. |
| **Namespace** | Beide | 1 bis 64 Zeichen aus `a-z`, `0-9`, `_` und `-`. Ohne Angabe folgt er dem Namen. Darf nicht `gateway` sein. Er darf nicht dem Namespace eines anderen Gateways entsprechen, damit beginnen oder ihn mit `-` erweitern. Fest, sobald das Gateway Things hat oder seine Box registriert ist. Umbenennen verschiebt keine bestehenden Things. |
| **Rollen** | Periscope | Die Rollen, mit denen das Gateway handelt, beschränkt auf das, was ein Gateway darf. Vorgabe: **Modellierer**. Sie können keine Rolle mit Berechtigungen vergeben, die Sie selbst nicht haben. |
| **Code gültig für** | Periscope | 1 Stunde bis 7 Tage. Vorgabe 1 Tag. |
| **Format der Konfigurationsdatei** | MQTT-Gerät | **Umgebungsdatei (.env)**, **JSON (.json)** oder **eWON-Flexy-BASIC-Parameter (.bas)**. |
| **Erlaubte Thing-Typen** | Bereich | Bis zu 200. Leer heißt jeder Thing-Typ. |
| **Thing-Limit** | Bereich | 0 bis 100.000, neben dem eigenen Thing des Gateways. Leer heißt, nur die Limits der Organisation gelten. |
| **Anlegen von Things** | Bereich | **Offen** legt Things innerhalb des Scopes an. **Gesperrt** legt auf keinem Weg welche an: Daten für ein unbekanntes Thing werden verworfen und gezählt, bestehende Things arbeiten weiter. |

## Status {#statuses}

| Status | Bedeutung |
| --- | --- |
| **Online** | Das Gateway-Thing ist verbunden: Seine eigene Zustandsmeldung kam in den letzten 15 Minuten an. |
| **Offline** | Registriert, und das Gateway-Thing ist nicht verbunden oder hat noch keine Zustandsmeldung. |
| **Wartet auf Onboarding** | Ein Onboarding-Code steht aus. |
| **Nicht registriert** | Kein gültiger Schlüssel und kein ausstehender Code. |
| **Unvollständig, bitte löschen** | Nur das Identitätsverzeichnis kennt das Gateway. Löschen Sie es und fügen Sie es erneut hinzu. |

## Limits {#limits}

| Limit | Wert |
| --- | --- |
| Periscope-Gateways pro Organisation | 1000 |
| Gateways, zu denen ein Thing gehört | 1 |
| Things, die in einer Aktion zugeordnet werden | 200 |
| Länge der Alternate-ID | 128 Zeichen |
| Lebensdauer des Zugriffstokens | 5 Minuten |
| MQTT-Batch | 500 Elemente, 1 MiB |
| Ereignisse pro Seite | bis zu 200 |

## MQTT-Verbindung {#mqtt-connection}

| Eintrag | Wert |
| --- | --- |
| Client-ID | `<tenant>:gateway:<gateway id>`, optional gefolgt von `:<suffix>` |
| Protokoll | MQTT 3.1.1 |
| QoS | 0 oder 1 |
| Topics | **Telemetrie-Topic** für ein Thing, **Batch-Topic** für ein Array, **Status-Topic** für den Zustand. Alle unter dem **Topic-Präfix** |

Felder eines Batch-Elements: `id` (erforderlich), `thingType`, `time`, `data`. Element- und Nachrichtenregeln stehen unter [Nachrichtenformat](../connect/message-format.mdx), Topics unter [MQTT-Topics und Client-ID](../connect/mqtt-topics.mdx).

## Zustands-Messwerte {#health-measures}

Das Gateway meldet diese Werte alle 5 Minuten über sich selbst (Interface `GatewayHealth`). `data` darf nicht leer sein. Senden Sie sie live; würde eine gepufferte Nachricht erneut gesendet, bliebe ein totes Gateway online.

| Name | Bedeutung | Einheit |
| --- | --- | --- |
| `uptime_s` | Laufzeit | s |
| `buffer_used_pct` | Belegter Puffer | % |
| `buffer_oldest_s` | Älteste gepufferte Nachricht | s |
| `errors_per_min` | Fehler pro Minute | 1/min |
| `clock_offset_ms` | Uhrenabweichung | ms |
| `sw_version` | Softwareversion (Tag) | |
| `link_type` | Verbindungsart (Tag) | |

Ein Periscope-Gateway ergänzt das Interface `PeriscopeAgent`: `outputs_failing`, `inputs_failing`, `output_p95_ms`, `restart_required`, `config_hash` und `last_apply`.

## Datenverkehr-Messwerte {#traffic-measures}

Die Plattform schreibt diese Werte etwa jede Minute in das Gateway-Thing (Interface `GatewayTraffic`). Sie setzen ein Gateway nie auf online.

| Messwert | Bedeutung |
| --- | --- |
| `traffic_messages_per_min` | Gespeicherte Nachrichten pro Minute |
| `traffic_values_per_min` | Gespeicherte Messwerte pro Minute |
| `traffic_things_active` | Things mit einer gespeicherten Nachricht im Fenster |
| `traffic_last_data_age_s` | Sekunden von der letzten gespeicherten Nachricht bis zum Fensterende |
| `discards_per_min` | Endgültig abgelehnte Nachrichten pro Minute, alle Gründe |
| `discards_<reason>_per_min` | Dasselbe je Grund, 0 wenn keine |

## Verwerfungsgründe {#discard-reasons}

| Grund | Gezählt, wenn |
| --- | --- |
| `identity_mismatch` | Die Nachricht nennt eine andere Organisation oder ein anderes Thing als ihre Verbindung |
| `not_member` | Der Eintrag des Things nennt ein anderes Gateway oder keines |
| `unknown_thing` | Das Thing oder sein Thing-Typ existiert nicht |
| `invalid` | Alles andere, was endgültig abgelehnt wird: nicht dekodierbar, fehlerhaft, Validierung nicht bestanden, falscher Thing-Typ für das Thing |
| `id_missing` | Ein Batch-Element hat keine `id` |
| `too_large` | Ein Batch ist größer als 1 MiB und wird ganz verworfen |
| `too_many` | Ein Batch hat mehr als 500 Elemente und wird ganz verworfen |

Eine Abfrage, die die Plattform nicht beantworten konnte, wird wiederholt und nicht verworfen.

## Abgelehnte Anlagen {#refused-creates}

Der Versuch eines Periscope-Gateways, ein Thing anzulegen, kann abgelehnt werden. **Abgelehnte Anlagen** im Tab **Bereich** zählt sie nach Grund, und der Tab **Ereignisse** listet jede einzelne.

| Grund | Bedeutung |
| --- | --- |
| **Thing-Limit erreicht** | Das Gateway hat so viele Things, wie sein Limit erlaubt. |
| **Anlegen gesperrt** | Die Einstellung **Anlegen von Things** ist **Gesperrt**. |
| **Außerhalb des Namespace** | Die Alternate-ID des Things beginnt nicht mit dem Namespace des Gateways. |
| **Thing-Typ nicht erlaubt** | Der Thing-Typ steht nicht in der Liste der erlaubten. |

## Ereignisse {#events}

Der Tab **Ereignisse** zeigt Änderungen am Gateway und an seinem Gateway-Thing, den Eintrag des Verzeichnisses zu seinen Schlüsseln und einem offenen Onboarding-Code (**Schlüssel registriert**, **Schlüssel verwendet**, **Onboarding-Code offen**) und abgelehnte Anlagen. Das Identitätsverzeichnis führt keine eigene Historie.
