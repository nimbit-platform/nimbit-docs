Stop a gateway from sending, hand its identity to a new box, or delete it. For how a gateway signs in, read [How gateways work](./how-gateways-work.mdx).

## Before you start

- To revoke a key or issue a new code or credential you need update permission on gateways. To delete a gateway you need delete permission.
- Know the gateway's type. A **Periscope** gateway has keys and onboarding codes. An **MQTT device** gateway has one credential.

## How fast it takes effect

| What | When it stops |
| --- | --- |
| A new MQTT login with the old credential | At once. The platform may remember a successful check for a few seconds. |
| An MQTT session that is already open | Within 10 minutes. Every gateway session ends after at most 10 minutes. |
| A Periscope box's HTTP and stream writes | When its current token expires, after 10 minutes at most. It gets no new token. |
| A Periscope sign-in with a revoked key | At once. A sign-in token the key already got works for 5 minutes at most. |

## Revoke a Periscope key

1. Open the gateway and select the **Access & keys** tab.
2. Under **Keys**, find the key and select **Revoke key**, then **Revoke**.

The box can no longer sign in with that key. If it was the gateway's last key, the gateway turns **Not enrolled**. It then gets no credential at all until a box enrolls again with a new onboarding code. If other keys remain, the gateway stays as it is and its box asks for a new credential at its next login.

## Replace a Periscope box

1. To cut off the old box at once, revoke its key first, as above.
2. Open the gateway's row menu and select **New onboarding code**, then **Issue code**. Choose how long the code is valid.
3. Copy the code. The earlier code stops working immediately, even if nobody redeemed it.
4. On the new box, enroll it: `periscope enroll -code ONB-XXXX-XXXX-XXXX-XXXX`, or paste the code into the setup screen. See [Add a gateway](./add-a-gateway.mdx).

Enrolling replaces every key of the gateway. The gateway keeps its name, namespace, scope and things, and the new box finds its things again by their alternate IDs. Until a box enrolls with the new code, the old keys keep working. So revoke the old key first when you must cut it off.

## Replace an MQTT device

1. Open the gateway's row menu and select **New credential**, then **Issue credential**.
2. Copy the **Password** or select **Download config**. IoT Breeze shows it once.
3. Put the new credential on the device or on its replacement.

Logins with the old password are refused at once. A connection that is already open ends within 10 minutes. The gateway keeps its things. Don't run the old and the new unit with the same client ID: two connections with one client ID evict each other. Give each its own `:<suffix>` to run them side by side.

## Remove a gateway

1. Open the gateway's row menu and select **Delete gateway**.
2. Confirm.

IoT Breeze deletes:

- the gateway record, and with it its keys and any pending onboarding code, or its MQTT credential;
- the gateway thing, `gateway-<gateway id>`.

The things the gateway created or was given stay. They are no longer on a gateway, so a message for one over the gateway's path would be discarded. Release or reassign them as you need; see [Manage the things behind a gateway](./things-behind-a-gateway.mdx). The gateway's ID is never reused.

The box can no longer sign in. Open MQTT sessions end within 10 minutes. To move a gateway to new hardware and keep its things, issue a new onboarding code instead of deleting it.

If the gateway thing can't be deleted along with the gateway, the gateway is gone and `gateway-<gateway id>` stays as an ordinary thing. Delete it by hand.

## End every MQTT gateway credential at once

Rotating the tenant's signing key ends the credentials that were signed with the rotated key. MQTT device gateways use the **Primary** key. After you rotate it, every MQTT gateway needs a **New credential**. The same rotation also cuts off every device credential of that key. Do it only when all of them must change; see [Create and rotate device credentials](../connect/credentials.mdx).

## Check that it worked

The gateway's status changes in the list: **Not enrolled** after the last key is revoked, **Waiting for onboarding** after a new code, **Online** once the new box or device sends its health. After a delete, the gateway is gone from the list.

## If it doesn't work

- **The old box still sends after a revoke**: wait up to 10 minutes for its MQTT session or HTTP token to end.
- **The code is refused**: a code works once and until its expiry. Issue another.
- **A new credential is refused**: the device still holds the old password, or a config file downloaded later, which holds a placeholder instead of the password. Load the password or file from the **New credential** result. Lost it? Issue another credential.
