Legen Sie die Zugangsdaten an, mit denen sich ein Gerät über MQTT oder HTTP verbindet, und ersetzen Sie sie ohne Unterbrechung. Wie sie verwendet werden: [Wie Geräte sich verbinden](./how-devices-connect.mdx).

## Bevor Sie beginnen {#before-you-start}

- Sie brauchen die Berechtigung, Gerätezugangsdaten für Things anzulegen. Ohne sie fehlen die Schaltflächen.
- Das Thing existiert und hat einen Thing-Typ. Siehe [Ein Thing registrieren](../model/register-thing.mdx).

Ein Thing hat einen Schlüsselplatz **Primär** und einen **Sekundär**. Mit zwei Plätzen stellen Sie Geräte zuerst auf die sekundären Zugangsdaten um und rotieren dann die primären.

| Kachel | Verwenden, wenn |
| --- | --- |
| **Basisauthentifizierung** | Der Client nur Benutzername und Passwort unterstützt. Das Passwort läuft nicht ab. |
| **JWT-Authentifizierung** | Sie ein Bearer-Token mit Ablaufdatum möchten. Gültigkeit: 30 Tage, 1, 2, 5 oder 7 Jahre oder eine frei gewählte Anzahl Tage. |
| **Geräteschlüssel** | Sie den Signaturschlüssel hinter beiden sehen oder rotieren müssen. |

## Schritte {#steps}

### Basic-Zugangsdaten anlegen {#create-basic-credentials}

1. Öffnen Sie das Thing (**Geräte › Things**) und gehen Sie zu **Verbindungen**.
2. Wählen Sie im Block **Nimbit** unter **Basisauthentifizierung** die Option **Primär** und dann **Anmeldedaten generieren**.
3. Kopieren Sie **Benutzername** und **Passwort**.

### Ein JWT-Token erzeugen {#create-a-jwt-token}

1. Wählen Sie unter **JWT-Authentifizierung** die Option **Primär** und dann **Token generieren**.
2. Wählen Sie **Läuft ab in**. Der Hinweis zeigt das genaue Datum.
3. Wählen Sie **Token generieren**.
4. Kopieren Sie **Benutzername**, **Token** und **Läuft ab am**.

:::warning Kopieren Sie das Token jetzt
Wer das Token besitzt, kann als das Gerät auftreten, bis es abläuft oder der Signaturschlüssel rotiert wird. Die Seitenleiste wird beim Schließen geleert. Wählen Sie **Neues Token generieren**, wenn Sie es verloren haben.
:::

### Die Verbindungsdaten lesen {#read-the-connection-details}

Wählen Sie **Verbindungsinformationen**. Die Seitenleiste **Geräteverbindung** zeigt **Gateway-URL**, **Benutzername**, **Client-ID**, die Topics **Telemetrie**, **Befehle** und **Fehler** sowie die HTTP-URLs unter **REST**. Jeder Wert hat eine Schaltfläche zum Kopieren. Der **Benutzername** ist für jeden Zugangsdatentyp derselbe.

Port und TLS unterscheiden sich je nach Deployment. Lesen Sie sie in der **Gateway-URL** ab: `mqtts://` bedeutet TLS.

### Den Geräteschlüssel rotieren {#rotate-the-device-key}

Rotieren Sie, um Zugangsdaten zu sperren, denen Sie nicht mehr trauen, oder um ein verlorenes Token zu ersetzen.

1. Stellen Sie Ihre Geräte auf die Zugangsdaten des anderen Platzes um.
2. Wählen Sie unter **Geräteschlüssel** die Option **Schlüssel anzeigen**, um zu prüfen, welcher Schlüssel in Gebrauch ist, und dann **Rotieren** beim Platz, den Sie stilllegen.
3. Bestätigen Sie. Die Meldung **Signaturschlüssel rotiert** erscheint.

Alle Basic-Zugangsdaten und alle Tokens, die mit diesem Schlüssel signiert wurden, funktionieren für neue Anmeldungen und Requests nicht mehr. Legen Sie danach neue an.

## Prüfen, ob es geklappt hat {#check-that-it-worked}

Verbinden Sie sich mit den neuen Zugangsdaten, wie in [Daten über MQTT senden](./mqtt.mdx) oder [Daten über HTTP senden](./http.mdx). Die alten Zugangsdaten werden abgelehnt: mit `401` über HTTP, mit einer verweigerten Verbindung über MQTT.

Eine bereits offene MQTT-Verbindung wird durch eine Rotation nicht geschlossen. Trennen Sie das Gerät, damit sie wirkt. Eine Token-Sitzung endet von selbst, wenn das Token abläuft.

## Wenn es nicht funktioniert {#if-it-doesnt-work}

- **Es gibt keinen Nimbit-Block**: Der Thing-Typ verwendet einen anderen Konnektor, zum Beispiel Azure IoT Hub. Dessen Block zeigt seine eigenen Zugangsdaten.
- **Der Schalter ist deaktiviert**: Ihr Tenant hat den Konnektor abgeschaltet.
- **Das Gerät wird nach einer Rotation abgelehnt**: Es verwendet noch Zugangsdaten des rotierten Schlüssels. Generieren Sie neue Zugangsdaten und aktualisieren Sie das Gerät.
- **Der Benutzername passt nicht**: Verwenden Sie den **Benutzernamen** desselben Things. Ein Token und ein Benutzername von verschiedenen Things werden abgelehnt.
