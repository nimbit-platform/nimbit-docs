Alles, was ein Gerät wissen muss, um sich mit dem IoT-Breeze-MQTT-Broker zu verbinden. Wie Sie eine Nachricht senden: [Daten über MQTT senden](./mqtt.mdx).

## Broker {#broker}

| Eintrag | Wert |
| --- | --- |
| Adresse | **Gateway-URL** unter **Verbindungsinformationen**, zum Beispiel `mqtt://<host>:1883`. |
| Port und TLS | Standard der Plattform ist Port `1883` ohne TLS. Ihr Deployment kann einen anderen Port oder TLS setzen: `mqtts://` in der **Gateway-URL** bedeutet TLS. |
| MQTT-Version | 3.1.1. |
| QoS | 0 und 1. Der Broker nimmt kein QoS 2 an. |
| Max. Payload | 4 MiB. |

Um Ihre Werte zu finden, öffnen Sie das Thing (**Einstellungen › Onboarding › Things**), gehen Sie zu **Verbindungen** und wählen Sie **Verbindungsinformationen**. Die Seitenleiste heißt **Geräteverbindung**.

## Zugangsdaten {#credentials}

| Einstellung | Wert |
| --- | --- |
| Benutzername | **Benutzername** aus den **Verbindungsinformationen**. Er ist die base64url-Kodierung von `<tenantId>/<deviceId>` und für jeden Zugangsdatentyp derselbe. |
| Passwort | Das Basic-**Passwort** oder das JWT-**Token**. Ein Passwort aus drei durch Punkte getrennten Teilen wird als Token behandelt. |

Eine JWT-Sitzung endet, wenn das Token abläuft. Eine Basic-Sitzung läuft nicht ab. Das Rotieren eines Schlüssels sperrt neue Anmeldungen mit den alten Zugangsdaten, beendet aber keine offenen Verbindungen.

## Client-ID {#client-id}

| Regel | Detail |
| --- | --- |
| Erforderliche Form | `<tenantId>:<deviceId>`, wie die **Client-ID** sie zeigt. |
| Mit Suffix | `<tenantId>:<deviceId>:<suffix>` wird ebenfalls akzeptiert. |
| Leer | Wird abgelehnt. Senden Sie immer eine Client-ID. |
| Alles andere | Wird mit `MQTT client id not allowed` abgelehnt. |

Zwei Verbindungen mit derselben Client-ID ersetzen sich gegenseitig. Verwenden Sie einen Suffix, wenn ein Gerät mehrere Clients betreibt.

## Topics {#topics}

| Richtung | Topic | Bedeutung |
| --- | --- | --- |
| Publish | `tenant/<tenantId>/device/<deviceId>/telemetry` | Das Gerät sendet [Nachrichten](./message-format.mdx). |
| Subscribe | `iot/tenant/<tenantId>/device/<deviceId>/cmd/#` | Befehle für das Gerät. |
| Subscribe | `iot/tenant/<tenantId>/device/<deviceId>/error` | Abgelehnte Nachrichten, mit Grund. |

`<deviceId>` ist die interne ID des Things, wie die **Verbindungsinformationen** sie zeigen, nicht die **Alternative Thing -ID** auf der Seite des Things.

Ein Gerät darf nur in sein eigenes Telemetrie-Topic veröffentlichen und nur seine eigenen Topics `cmd` und `error` abonnieren. Alles andere wird abgelehnt.

## Zustellung {#delivery}

| Topic | Verhalten |
| --- | --- |
| Telemetry | Wird mit QoS 0 oder 1 angenommen. |
| `cmd/#` | Wird mit QoS 0 zugestellt, auch bei einem QoS-1-Abonnement. Ein Befehl wird für ein Gerät, das offline ist, nicht in eine Warteschlange gestellt. |
| `error` | Ein Hinweis für jede Nachricht, die nach der Annahme abgelehnt wurde, etwa bei einem unbekannten Thing-Typ. Best Effort. |

Eine Nachricht mit ungültigem JSON, fehlendem `thingType`, ohne Inhalt oder mit einem `tenant` oder einer `id`, die nicht zum Topic passt, wird auf Broker-Seite ohne Hinweis im Topic `error` verworfen.

## Fehlerhinweis {#error-notice}

Ein Hinweis im Topic `error` ist ein JSON-Objekt:

| Feld | Bedeutung |
| --- | --- |
| `tenant`, `thing`, `thingType` | Was die Nachricht genannt hat. |
| `stage` | Der Verarbeitungsschritt, der sie abgelehnt hat. |
| `error` | Der Grund. |
| `source` | Woher die Nachricht kam. |
| `time` | Wann sie abgelehnt wurde. |
| `message` | Die Nachricht, wie tsflux sie vorliegen hatte. |
